ReaUI Builder

Визуальный редактор макетов для интерфейсов ReaImGui.

Разместите элементы окна на холсте и экспортируйте Lua-код ReaImGui для виджетов, рисунков и стилей. Builder использует логические координаты макета: масштаб просмотра не меняет экспортируемые координаты. Preview приблизительно показывает вид работающего интерфейса.

Это руководство описывает версию 1.0.3.

01. Назначение

ReaUI Builder работает как локальный HTML-файл и не требует установки, сервера или сборки. Все необходимые стили, иконки, контракты виджетов и генератор кода находятся внутри файла.

Builder предназначен для создания макета интерфейса, а не логики скрипта. В нём можно задать положение и размер виджетов, их подписи и основные параметры, а затем экспортировать структуру окна в Lua.

Builder не создаёт DSP, логику проекта и обработку событий. Для интерактивных виджетов в экспортируемом коде оставляются места для пользовательской логики, отмеченные комментариями -- TODO.

  • Результат работы: Lua-код для ReaImGui 0.10
  • Виджеты: 48 размещаемых типов в 41 семействе и два автоматически управляемых типа — TabItem и TableCell
  • Примитивы рисования: 7 — прямоугольник, круг, полигон, линия, текст, треугольник и дуга
  • Формат проекта: JSON с номером версии

В основе Builder лежат два принципа.

Абсолютное размещение

ImGui по умолчанию располагает виджеты последовательно. Builder использует абсолютное позиционирование: WindowPadding и ItemSpacing устанавливаются в ноль, а перед каждым виджетом задаётся явная позиция курсора.

Благодаря этому координаты элементов на холсте соответствуют координатам в REAPER.

Контракты виджетов

Для каждого типа виджета задан контракт — набор правил, определяющих его размер по умолчанию, допустимые изменения размеров, способ применения ширины и положение подписи.

Холст, инспектор и генератор кода используют общие контракты с дополнительными правилами для отдельных типов. У Checkbox фиксированы оба размера, у Slider — высота и внешнее положение подписи, у ColorPicker высота вычисляется. Далее описаны различия между областью редактирования и размерами в экспорте.

02. Быстрый старт

Откройте HTML-файл в современном браузере. Builder работает локально через file://; для редактирования макета и генерации кода интернет не нужен. Для запуска экспортированного Lua-скрипта необходим REAPER с установленным ReaImGui 0.10.

  1. Откройте вкладку Canvas в правой панели и задайте размер создаваемого окна. По умолчанию используется размер 600 × 400 px.
  2. Выберите виджет в одной из категорий верхней панели. Контейнеры Group, Style, Table, Header, Tree и Tabs также доступны постоянными ярлыками в левой палитре. Категории: Buttons & Toggles, Display, Input, Selection, Color, Layout.
  3. Щёлкните по холсту. Левый верхний угол виджета будет установлен в точку щелчка с учётом привязки к сетке.
  4. Настройте выбранный виджет в панели Selection: измените подпись, диапазон значений, флаги, координаты и размер.
  5. Нажмите Export, устраните ошибки в панели проверки и нажмите download .lua. Либо нажмите copy и сохраните код в файл .lua. Загрузите файл через окно Actions в REAPER и запустите его.

Иллюстрация. Рабочее пространство при запуске. Слева находится палитра инструментов. В центре — холст с макетом окна и линейками. Справа — контекстная панель Canvas / Elements / Info и инспектор Selection. Внизу расположена статусная строка.

Совет — сохраняйте проект. Builder автоматически сохраняет аварийный черновик в памяти браузера и при следующем запуске может предложить его восстановить. Это страховка, а не замена файлу проекта: перед закрытием вкладки выберите File → Save Project и храните полученный JSON вместе со скриптом.

03. Рабочее пространство

В режиме Editor над каждым виджетом отображается серая метка с его именем.

Контейнеры Panel, TabBar и Table дополнительно отображают полосу заголовка. Щёлкните по этой полосе, чтобы выбрать сам контейнер, а не расположенный внутри него элемент.

Иллюстрация. Макет в режиме Editor. Служебные подписи и полосы контейнеров помогают редактировать структуру макета и не являются частью экспортируемого интерфейса.

3.1 · Верхняя панель и меню

В верхней панели находятся четыре меню, глобальные команды и категории виджетов.

Меню Команды
File New Project · Save Project · Load Project
Edit Undo · Redo · Copy · Paste · Delete · Duplicate · Select All · Deselect All · Clear All
View Dark mode · Grid · Snap to grid · Reference grid in export · Widget footprints · Zoom to fit · Actual size (100%)
Help Keyboard Shortcuts · Report a Bug… · About

Undo и Redo недоступны, если соответствующая история действий пуста.

Reference grid in export включает пурпурную измерительную сетку с шагом 50 px. В отличие от обычной сетки, она также попадает в экспорт. На вкладке Canvas эта же настройка называется Audit grid.

Snap to grid включает и отключает привязку к сетке. Активные пункты меню View отмечены галочкой.

Команда Clear All удаляет все элементы с холста после подтверждения.

Кнопка Export открывает окно со сгенерированным кодом.

Справа расположены шесть категорий виджетов. Щёлкните по категории, чтобы открыть панель с входящими в неё виджетами. Повторный щелчок закрывает панель.

3.2 · Панель виджетов

Панель содержит полный список виджетов, разделённый на шесть категорий.

Чтобы добавить виджет, откройте нужную категорию, выберите его, а затем щёлкните по холсту.

Если содержимое категории не помещается по ширине, панель можно прокручивать горизонтально колесом мыши.

При запуске открыта категория Display. Повторный щелчок по её кнопке закрывает панель; пока ни одна категория не открыта, панель остаётся пустой — это штатное поведение.

3.3 · Левая палитра

В левой палитре находятся постоянные инструменты:

  • Select и Hand;
  • семь инструментов рисования;
  • ярлыки шести контейнеров: Group, StyleRegion, Table, CollapsingHeader, TreeNode и TabBar.

Select — инструмент по умолчанию. После размещения объекта Builder автоматически возвращается к нему.

Hand используется для панорамирования рабочей области. Временно включить тот же режим из любого другого инструмента можно, удерживая Space.

Инструменты рисования по умолчанию работают однократно: после создания фигуры снова включается Select.

Чтобы нарисовать несколько прямоугольников, окружностей, линий, треугольников или дуг, удерживайте Shift при выборе инструмента, затем отпустите клавишу перед рисованием. Инструмент остаётся активным до выбора другого инструмента или нажатия Esc; в строке состояния появляется [sticky]. Polygon, Text и размещение виджетов после завершения возвращают Select.

3.4 · Область холста

В центральной части рабочего пространства отображается макет окна скрипта: заголовок MyPlugin, область будущего интерфейса и рабочее пространство вокруг неё.

Размер области макета соответствует размеру экспорта. Заголовок служит напоминанием о собственной полосе заголовка ImGui; её высота учитывается в экспортируемом коде:

OUTER_H = H + высота заголовка

Над холстом и вокруг него расположены дополнительные элементы управления:

  • Editor / Preview — переключатель режима отображения в верхней центральной части. Подробнее см. §13.
  • Theme — выбор темы справа над холстом. Подробнее см. §12.
  • Линейки — расположены сверху и слева и показывают координаты макета с учётом текущего масштаба.
  • Маркер изменения размера ⇲ — расположен в правом нижнем углу макета. Перетащите его, чтобы изменить размер холста. Это эквивалентно изменению W и H на вкладке Canvas.
  • Баннер Preview — появляется в режиме Preview, если макет содержит виджеты, которые Builder может показать только схематично.

3.5 · Правая панель

Правая панель состоит из двух частей: контекстной панели с вкладками Canvas / Elements / Info и инспектора Selection.

Info

Когда выбран виджет или активирован инструмент его размещения, вкладка Info показывает приблизительный внешний вид виджета в ImGui и краткое описание его назначения.

Выбор виджета на панели виджетов или в левой палитре сам открывает вкладку Info, и она остаётся открытой после размещения: созданный объект заменяет в ней предварительный показ.

Info показывает пример и описание одного выделенного виджета или рисунка либо активного инструмента размещения. Когда такого контекста нет, выводится сводка проекта.

Elements

Вкладка Elements показывает все объекты макета в виде дерева.

Дочерние элементы отображаются с отступом под своими контейнерами. Щёлкните по строке, чтобы выбрать соответствующий объект на холсте.

Canvas

На вкладке Canvas находятся параметры самого макета: размер окна, режим фона, видимость сетки и её шаг.

Здесь же расположен выбор цвета фона с пипеткой, недавними образцами и настройкой прозрачности. Код цвета показан в нижней строке вкладки и меняется прямо во время выбора; в режиме Custom его можно ввести вручную, а в режиме Default там показано название темы, за которой следует холст.

Заголовок окна редактируется не здесь, а на самом макете: щёлкните по названию в шапке холста — см. §11.

Selection

Инспектор Selection формируется по контракту выбранного виджета. В нём отображаются только те параметры, которые применимы к этому типу.

Поэтому набор полей меняется при выборе разных виджетов: у простых элементов отображается только несколько основных параметров, а у виджетов с диапазонами, форматированием или дополнительными флагами инспектор заметно больше.

Поля инспектора сгруппированы в разделы: Main — подпись, имя, значения и диапазоны; Structure — вкладки и таблицы; Appearance — цвета, скругления, толщина; Advanced — форматы и флаги. Ниже, без заголовка, идут координаты и размер. Пустые разделы для выбранного типа не отображаются.

Если выделено несколько объектов, инспектор переключается в режим пакетного редактирования — см. §5.6.

Все параметры инспектора описаны в §8. Полный список параметров для каждого типа виджета приведён в приложении B.

3.6 · Статусная строка

В статусной строке отображаются:

  • текущий масштаб и кнопка вписывания макета в окно;
  • активный инструмент и подсказка по его использованию;
  • координаты курсора;
  • X, Y, W и H текущего выделения;
  • состояние привязки к сетке;
  • количество элементов.

Эта же область используется для служебных сообщений.

Если Builder отклоняет размещение, вместо отдельного диалогового окна в статусной строке ненадолго появляется сообщение, например:

blocked: overlaps existing widget

или

blocked: container too large for target

04. Основные понятия

4.1 · Виджеты и рисунки

Объекты на холсте делятся на два типа: виджеты и рисунки. Они различаются по интерактивности, вложенности, правилам перекрытия, порядку отрисовки и способу экспорта.

Виджеты Рисунки
Что это Виджеты ImGui: кнопки, слайдеры, таблицы и другие интерактивные элементы Геометрия в draw list окна
Интерактивность Нативные элементы управления могут быть интерактивными; виджеты отображения служат для вывода информации Нет; используются для оформления
Экспорт ImGui_Button, ImGui_SliderDouble, … DrawList_AddRect, AddCircle, …
Перекрытие Предотвращаются проверками размещения; исключения описаны в §4.7 Допускается; учитывается порядок наложения
Вложенность Допускается внутри контейнеров Не поддерживается
Отрисовка Поверх рисунков Под всеми виджетами

Рисунки используются для элементов, которым не соответствует отдельный виджет ImGui: например, корпуса индикатора, рамки вокруг секции, дуги шкалы или логотипа.

Виджеты используются для элементов, с которыми взаимодействует пользователь.

4.2 · Семейства и варианты

Палитра Builder организована по семействам, а экспортируемый код — по конкретным типам виджетов.

Семейство объединяет варианты одного элемента управления. Например:

  • Slider → SliderInt / SliderDouble — по умолчанию Double
  • Drag → DragInt / DragDouble — по умолчанию Double
  • Input → InputInt / InputDouble — по умолчанию Double
  • VSlider → VSliderInt / VSliderDouble — по умолчанию Double
  • DragRange → DragIntRange2 / DragFloatRange2 — по умолчанию Double
  • ColorEdit → ColorEdit3 / ColorEdit4 — по умолчанию RGB
  • ColorPicker → ColorPicker3 / ColorPicker4 — по умолчанию RGB

Если у семейства есть несколько вариантов, в верхней части инспектора появляется строка variant.

Вариант можно выбрать во время предварительной настройки, пока активен инструмент размещения. После создания виджета строка показывает выбранный вариант, но изменить его нельзя. Чтобы использовать другой вариант, удалите виджет и разместите его заново.

У семейств без вариантов имя в палитре и тип в экспортируемом коде различаются только уровнем обозначения: например, Slider — имя семейства в интерфейсе Builder, а SliderDouble — конкретный тип виджета в коде.

Некоторые названия в палитре короче имён контрактов в руководстве: Hint = HelpMarker, RadioButton = RadioButtonEx, TextLink = TextLinkOpenURL, Multiline = InputTextMultiline, Style = StyleRegion, Header = CollapsingHeader, Tree = TreeNode, Tabs = TabBar.

4.3 · Координаты и привязка

Координаты x и y каждого вложенного объекта хранятся относительно его родителя.

Например, кнопка в левом верхнем углу панели может хранить координаты (4, 28), хотя сама панель расположена так, что абсолютная позиция кнопки на макете равна (24, 278).

При перемещении панели кнопка перемещается вместе с ней, а её собственные координаты (4, 28) не изменяются.

В инспекторе и экспортируемом коде используются абсолютные координаты макета. Builder выполняет необходимый пересчёт автоматически.

Привязка к сетке

При включённой привязке координаты округляются до выбранного шага сетки.

Шаг задаётся на вкладке Canvas:

  • 2 px
  • 5 px
  • 10 px — значение по умолчанию

Привязка действует при размещении, перемещении и изменении размера объектов.

Чтобы отключить её, выберите View → Snap to grid. Текущее состояние отображается в статусной строке.

Примечание — шаг сетки и крупная сетка. Выбранный шаг определяет привязку и расстояние между тонкими линиями сетки. Толстые линии с шагом 50 px постоянны и служат только визуальным ориентиром. Привязка к ним не выполняется. При сильном уменьшении масштаба Builder может отображать сетку с более крупным визуальным шагом, но координаты по-прежнему привязываются к значению, выбранному в Canvas.

4.4 · Контракты размеров

ImGui не позволяет независимо задавать ширину и высоту для всех типов виджетов. Builder воспроизводит эти ограничения на холсте, чтобы макет можно было корректно перенести в код.

Для высоты используются четыре режима:

Режим Поведение
explicit-size Контракт задаёт явную область макета. Button, Panel и подобные элементы передают размеры в ImGui; у некоторых типов высота вычисляется или переводится в число строк.
native-fixed Высоту определяет ImGui: обычно это одна высота фрейма, около 20 px. Так работает большинство виджетов ввода.
native-content Высота определяется содержимым, например текстом.
native-line Высота соответствует одной разделительной линии.

При фиксированной высоте остаются только боковые маркеры, если ширину можно менять, а поле H доступно только для чтения. У Checkbox, ArrowButton и SmallButton маркеров изменения размера нет; ширина SmallButton зависит от подписи. У ColorPicker доступны только боковые маркеры, а высота вычисляется из ширины и флагов.

↑ height fixed by ImGui или ↑ size fixed by ImGui — в зависимости от виджета.

Ширину такого виджета при этом можно изменять.

ColorPicker. Новый picker имеет ширину 200 px и включённый NoSidePrev; Builder резервирует высоту 246 px. H доступно только для чтения и зависит от ширины и флагов. Включение бокового preview добавляет 60 px к резервируемой ширине, сохраняя ширину самого picker. В SetNextItemWidth передаётся ширина picker, а не всей резервируемой области.

ListBox. Экспортёр переводит H в число видимых строк: max(2, round(H / 18)). H не передаётся как высота в пикселях. TextWrapped также имеет область макета в Builder, но высоту текста определяет ImGui.

В контрактах используются четыре режима ширины:

  • explicit-size — ширина передаётся непосредственно в вызов виджета;
  • next-item-width — перед вызовом используется SetNextItemWidth;
  • content-or-widget-box — область на холсте резервирует место под содержимое, а фактический размер рассчитывает ImGui.
  • widget-box-preview — сохранённая область резервирует место в Builder; в экспортированном интерфейсе Checkbox и RadioButtonEx используют собственные размеры ImGui.

4.5 · Подписи

По умолчанию ImGui выводит подпись рядом с виджетом в рамках того же вызова. При абсолютном размещении это может приводить к тому, что текст оказывается за пределами области, заданной в Builder.

Поэтому Builder использует два способа отображения подписей.

Встроенная подпись

Используется у Button, SmallButton, Selectable, RadioButtonEx, а также у заголовков и вкладок нативных контейнеров. У Group и StyleRegion нет видимого заголовка в экспорте.

Текст передаётся непосредственно в вызов ImGui и отображается как часть виджета.

Внешняя подпись

Используется у слайдеров, полей ввода, Combo, Checkbox, цветовых и некоторых других виджетов.

Сам виджет получает скрытый идентификатор, например:

"##Slider_4"

Видимая подпись выводится отдельно через draw list над верхней границей виджета. На холсте Builder показывает её в том же положении.

Для такой подписи требуется около 14 px дополнительного пространства по вертикали. Оно не входит в собственную область виджета.

Оставляйте достаточный зазор между элементами. Например, если разместить два слайдера с вертикальным шагом 20 px, подпись нижнего может наложиться на верхний.

4.6 · Контейнеры и вложенность

Builder поддерживает семь типов контейнеров:

  • Panel
  • Group
  • StyleRegion
  • CollapsingHeader
  • TreeNode
  • TabBar
  • Table

Кроме того, используются TabItem и TableCell. Builder создаёт их автоматически; вручную разместить эти элементы нельзя.

Вложенность определяется положением элементов на холсте.

Если разместить виджет внутри рабочей области контейнера, он становится его дочерним элементом. Если вынести его за пределы контейнера, он возвращается на уровень макета или становится дочерним элементом другого подходящего контейнера.

Отдельной команды «добавить в контейнер» нет.

Каждый из семи размещаемых контейнеров резервирует сверху полосу 24 px для редактирования и размещения. Структурные дочерние элементы TabItem и TableCell не добавляют ещё одну такую полосу.

Сама служебная полоса не экспортируется. Координаты дочерних элементов сохраняют зарезервированный отступ; нативные заголовки и вкладки рисует ImGui.

При изменении размера контейнера Builder смещает дочерние элементы в сторону его внутренней области. Размеры ячеек таблицы и страниц вкладок следуют за родителем. Оставляйте достаточно места для содержимого: смещение не уменьшает размеры дочерних элементов, а проверки при перетаскивании маркеров и вводе в инспекторе различаются.

Контейнеры можно вкладывать друг в друга. Например:

TabBar → TabItem → Panel → Button

В экспортируемом коде соответствующие вызовы ImGui будут вложены в том же порядке.

Цепочка родителей выбранного виджета отображается в строке parent инспектора.

4.7 · Запрет перекрытия

Builder проверяет занимаемые виджетами области при размещении и перемещении, чтобы предотвращать пересечения. Эти проверки действуют не во всех операциях одинаково: в частности, вставка контейнеров или дочерних элементов в существующего родителя не использует тот же поиск свободного места, что вставка отдельного виджета верхнего уровня.

В ImGui виджеты обрабатываются в порядке вызовов. Если интерактивные элементы перекрываются, они могут перехватывать друг у друга ввод мыши, поэтому Builder не допускает такие макеты.

Проверка выполняется по-разному в зависимости от операции:

  • Размещение нового виджета. Если позиция занята, размещение отклоняется, а в статусной строке появляется сообщение.
  • Перемещение одного виджета. Если выбранная позиция занята, Builder ищет ближайшую свободную позицию на сетке.
  • Перемещение или изменение размера группы. Проверяется вся группа. Если допустимое положение не найдено, операция отменяется и объекты возвращаются в исходное состояние.

Некоторые виджеты занимают больше места, чем кажется по их видимой части.

Например, в область ColorPicker входит боковая полоса предпросмотра, а Checkbox занимает весь квадрат своего элемента.

Проверка перекрытия выполняется по полной занятой области виджета. Поэтому размещение иногда может быть отклонено даже там, где визуально остаётся свободное место.

4.8 · Имена объектов

При создании каждый объект автоматически получает имя с номером:

Button_2
Slider_4
Panel_6

Имя отображается на вкладке Elements и используется при генерации Lua-кода.

Например, из имени Slider_4 формируются:

  • константа позиции SLIDER_4_X;
  • переменная состояния Slider_4_val;
  • идентификатор ImGui "##Slider_4".

Объекты можно переименовывать.

Используйте латинские буквы, цифры и символ _. Другие символы при экспорте заменяются на _.

Имена рекомендуется делать уникальными. Если после нормализации два имени совпадут, панель проверки покажет предупреждение, а экспортёр детерминированно добавит к повторяющемуся имени суффикс _2, _3 и так далее. Идентификаторы ImGui останутся уникальными.

05. Работа с объектами

5.1 · Размещение виджетов

Выберите виджет, затем разместите его на холсте одним из двух способов.

Щелчок создаёт виджет стандартного размера, заданного его контрактом.

Нажмите и потяните, чтобы задать размер при размещении. По каждой оси размер протяжки не менее 10 пикселей макета после привязки заменяет размер по умолчанию; меньший размер использует значение по умолчанию. Фиксированные и вычисляемые размеры подчиняются правилам виджета.

Например, Button можно сразу разместить размером 200 × 70 px. У Slider протягивание может задать ширину 300 px, но его высота останется фиксированной.

После размещения снова включается Select, а созданный виджет остаётся выделенным. Его параметры можно сразу изменить в инспекторе.

Предварительная настройка

Пока активен инструмент размещения, инспектор Selection показывает параметры, которые можно настроить до создания виджета.

В версии 1.0.3 часть полей этой формы работает некорректно: значения min, max, format, числовые флаги, components, tooltip и bullet после размещения не переносятся в созданный виджет.

При размещении переносятся вариант, подпись, текст-заполнитель, значение LabelText, URL, направление стрелки, группа радиокнопок и значение радиокнопки — если соответствующее поле применимо. Имя назначается автоматически. Остальные свойства задавайте после размещения: их предварительные значения в новый виджет не копируются.

Команда Reset возвращает предварительные параметры к значениям по умолчанию.

Повторный щелчок по активному инструменту отменяет его.

Размещение через контекстное меню

Виджет можно добавить и без панели виджетов.

Щёлкните правой кнопкой мыши по холсту. В контекстном меню отображаются все типы виджетов, сгруппированные по категориям.

Выбранный виджет будет размещён в точке щелчка.

Этот способ удобен, если вы уже знаете название нужного типа и не хотите открывать соответствующую категорию в верхней панели.

5.3 · Перемещение и изменение размера

Чтобы переместить выбранный объект, перетащите его.

Чтобы изменить размер, перетащите один из маркеров выделения.

Обе операции учитывают привязку к сетке.

Количество доступных маркеров определяется контрактом виджета:

  • восемь — если ширину и высоту можно изменять свободно;
  • два боковых — если высота фиксирована, а ширину изменять можно;
  • маркеры отсутствуют — если размер полностью определяет ImGui.

Для точного размещения используйте поля position и size в инспекторе.

Эти поля используют абсолютные координаты макета и учитывают Snap to grid. Отключите привязку для ввода координат с шагом 1 пиксель. Значения обрабатываются как целые числа; отрицательные координаты заменяются нулём.

Стрелки сдвигают выделение на один шаг сетки; при выключенной привязке — на 1 px. С удержанием Shift сдвиг увеличивается в десять раз. Для ввода точных координат используйте поля position в инспекторе.

5.4 · Копирование, дублирование и удаление

Copy / Paste

Cmd/Ctrl + C и Cmd/Ctrl + V

Начальная позиция вставки смещена на 20 px по обеим осям. Для отдельного виджета верхнего уровня Builder при необходимости ищет свободную позицию рядом; если её нет, этот виджет не вставляется. Повторные вставки увеличивают предполагаемое смещение.

У примитива Line при Copy/Paste в 1.0.3 координаты концов не смещаются. Поэтому вставленная линия может лежать поверх исходной; переместите выделенную копию, чтобы разделить их.

При копировании контейнера копируется всё его поддерево с сохранением отношений между родительскими и дочерними элементами.

Если исходный родитель всё ещё существует, вставленная копия размещается внутри него.

Duplicate

Cmd/Ctrl + D

Создаёт копию и сразу размещает её — эквивалент последовательных команд Copy и Paste.

Alt + перетаскивание

Начните перетаскивание с удержанием Alt, чтобы перемещать копию объекта, оставив оригинал на месте.

Этот способ работает и для множественного выделения.

Delete

Del или Backspace

При удалении контейнера удаляются и все его дочерние элементы.

Подтверждение не запрашивается. Операцию можно отменить командой Undo.

5.5 · История изменений

Builder хранит 50 шагов истории.

Последовательные изменения одного и того же свойства, выполненные в пределах 600 мс, объединяются в один шаг. Например, несколько быстрых изменений значения max не создают отдельную запись истории для каждого промежуточного значения.

Команда Undo восстанавливает не только состояние объектов, но и выделение, которое было активно на соответствующем шаге.

При загрузке проекта история очищается. Отменить изменения, выполненные до загрузки, после этого нельзя.

5.6 · Пакетное редактирование

Когда выделено больше одного объекта, инспектор показывает их количество и состав по типам, а из свойств — только те, которые есть у всех выделенных объектов. Например, для кнопки и флажка это подпись, всплывающая подсказка и маркер списка.

Если значение свойства у выделенных объектов различается, поле показывает Mixed. Пока вы не введёте значение, свойство не изменяется ни у одного объекта.

Поля ΔX / ΔY смещают всё выделение с проверкой границ рабочей области и пересечений. Рабочая область шире экспортируемого макета, поэтому виджет может оказаться за границей экспорта. Если выделены контейнер и его дочерний элемент, дочерний элемент перемещается вместе с контейнером один раз.

Любое пакетное изменение — одно действие в истории: один Undo возвращает исходные значения всем объектам выборки.

Примечания к каталогу

Slider, Drag и Input. Slider имеет дорожку и границы диапазона, Drag меняет значения горизонтальным перетаскиванием, Input позволяет вводить числа. Поля инспектора различаются: Slider предоставляет границы и флаги, Drag добавляет скорость, а однокомпонентный Input — шаг. У SliderAngle и семейств с суффиксом N свои наборы полей; см. приложение B.

Семейства с суффиксом N (SliderN, DragN, InputN). В экспорте создаётся reaper.new_array на количество элементов, заданное в поле array size, и управление выполняется одним вызовом. Обычные семейства вместо этого используют поле components со значением от 1 до 4: генерируются вызовы вида SliderDouble2 или DragInt3 с отдельными скалярными переменными.

HelpMarker. В экспорте выводится как неактивный символ (?). Текст подсказки берётся из поля tooltip, а не из подписи.

Combo и ListBox. В экспорт добавляются пять элементов-заглушек: item_0…item_4 и Item 1…Item 5. Списки элементов в этой сборке не редактируются, задайте их в готовом коде.

RadioButtonEx. Кнопки с одинаковым значением в поле group используют общую переменную состояния, каждой кнопке задаётся собственное значение в поле radio value. Так в экспорте реализуется взаимное исключение.

07. Контейнеры

Общие свойства контейнеров описаны в §4.6: полоса заголовка высотой 24 px, геометрическая вложенность, корректировка положения дочерних элементов при изменении размера, каскадное удаление. Ниже описано, чем контейнеры различаются.

7.1 · Panel

Panel — это дочернее окно ImGui: область с рамкой, при необходимости прокручиваемая. Применяется для боковых панелей, блоков настроек и групп виджетов с видимой границей.

  • border. Отображает рамку. Включён по умолчанию. При выключенном параметре область остаётся невидимой, но по-прежнему обрезает и прокручивает содержимое.
  • h-scroll. Добавляет горизонтальную полосу прокрутки. Без неё содержимое шире панели обрезается.
reaper.ImGui_BeginChild(ctx, "Output##Panel_6", 220, 140, reaper.ImGui_ChildFlags_Borders(), 0)
  -- дочерние виджеты, для каждого задаётся SetCursorScreenPos
reaper.ImGui_EndChild(ctx)

При теме, отличной от Default, каждый Panel использует цвет фона дочернего окна из этой темы. Builder применяет цвет перед BeginChild и снимает переопределение сразу после вызова, до вывода содержимого. Отдельного поля цвета фона для каждого Panel нет.

7.2 · Group

Group не имеет ни рамки, ни фона и ничего не отображает. В экспорте выводятся вызовы BeginGroup и EndGroup, после чего ImGui обрабатывает вложенные виджеты как один элемент при раскладке и обработке попадания указателя.

Используйте Group, когда несколько виджетов должны перемещаться вместе в Builder и составлять один логический блок в экспортируемом коде. Если границу блока нужно видеть, используйте Panel.

В режиме Preview Group отображается штриховкой.

7.3 · StyleRegion

StyleRegion — это область, которая применяет стилевые переопределения к вложенным виджетам. Остальной макет переопределения не затрагивают. Это единственный способ управлять внешним видом отдельных виджетов.

Иллюстрация. Инспектор StyleRegion. У каждого переопределения есть флажок. Снятый флажок означает, что параметр не изменяется, поэтому область может переопределить только цвет кнопок и унаследовать остальные параметры.

Переопределение Экспорт
text color PushStyleColor(Col_Text)
frame bg PushStyleColor(Col_FrameBg)
button color PushStyleColor(Col_Button)
rounding PushStyleVar(StyleVar_FrameRounding)
selectable align PushStyleVar(StyleVar_SelectableTextAlign, x, y), оба значения от 0 до 1
font CreateFont(family, flags) при запуске, затем PushFont(ctx, font, size) вокруг дочерних виджетов

Builder создаёт каждое уникальное сочетание семейства и начертания одним вызовом CreateFont и прикрепляет шрифт к контексту до первого кадра. PushFont выполняется после стилевых переопределений, а соответствующий PopFont — перед их снятием, поэтому шрифт применяется только к виджетам внутри StyleRegion.

Примечание. В Preview StyleRegion применяет поддерживаемые переопределения цвета, скругления и шрифта к дочерним элементам. Переопределение цвета текста действует и на внешние подписи, а также Text, Separator, SeparatorText, LabelText и BulletText в draw list: Builder вычисляет их цвет при генерации Lua. Маркер Aa в служебном заголовке обозначает переопределение шрифта.

7.4 · CollapsingHeader и TreeNode

Оба контейнера сворачивают содержимое во время работы плагина. CollapsingHeader — полоса во всю ширину, TreeNode — узел с отступом и стрелкой. TreeNode экспортируется с флагом TreeNodeFlags_DefaultOpen, поэтому при запуске узел раскрыт.

У TreeNode есть настройка hdr color. В режиме default выбирается чёрный или белый текст для контраста с фоном холста; в режиме custom используется выбранный цвет. Экспорт применяет цвет к подписи узла в обоих режимах.

В Builder оба контейнера всегда отображаются раскрытыми.

7.5 · TabBar

Выделите заголовок контейнера Tabs, чтобы открыть список tabs. Изменяйте имена в строках, нажимайте × для удаления страницы с её содержимым или добавляйте новую страницу. Кнопка × не удаляет последнюю оставшуюся страницу.

При размещении TabBar создаётся с двумя вкладками. Щелчок по вкладке на холсте переключает активную страницу; отображается и обрабатывается только её содержимое. Виджеты, размещённые на странице, принадлежат соответствующему элементу TabItem.

В экспорте вызовы BeginTabItem и EndTabItem вкладываются в BeginTabBar и EndTabBar, а виджеты каждой страницы — внутрь своего элемента.

7.6 · Table

Иллюстрация. Инспектор Table. Счётчики строк и столбцов, подпись и режим ширины для каждого столбца, флажок строки заголовков, четыре флага таблицы и общая политика размеров.

Table — сетка ячеек-контейнеров. Число строк и колонок — от 1 до 16; новая таблица содержит 3 × 3 ячейки. Если при уменьшении удаляются заполненные ячейки, в диалоге OK удаляет их содержимое, а Cancel сохраняет виджеты на верхнем уровне. Cancel сохраняет содержимое, но не отменяет изменение размера таблицы.

Параметр Описание
columns / rows От 1 до 16 по каждой оси. Увеличение создаёт ячейки; уменьшение удаляет их и предлагает выбрать, что делать с содержимым.
Ширина столбца Имеет три значения. При значении Auto флаг не задаётся. При значении Fix задаётся WidthFixed и ширина в пикселях. При значении Str задаётся WidthStretch и весовой коэффициент.
header row Добавляет вызов TableHeadersRow и резервирует на холсте полосу подписей высотой 18 px.
Borders Границы ячеек.
RowBg Чередующийся фон строк.
Resizable Разрешает изменять ширину столбцов во время работы плагина.
ScrollY Включает вертикальную прокрутку. Только при включённом ScrollY высота таблицы передаётся в ImGui.
sizing Политика размеров для столбцов со значением Auto: SizingFixedFit или SizingStretchSame.

Builder вычитает из высоты таблицы служебную полосу 24 px и, если включены заголовки колонок, полосу 18 px, затем делит остаток на число строк. Округлённый результат передаётся в TableNextRow как минимальная высота. Ячейки выводятся по строкам; их дочерние элементы сортируются по Y, затем по X. При этом экспортёр продолжает задавать дочерним виджетам абсолютную позицию курсора — автоматической потоковой раскладки здесь нет.

Примечание. При размещении в ячейке позиция сохраняется, насколько возможно, затем ограничивается внутренней областью с отступом 4 px; выступающие размеры при необходимости уменьшаются. Центрирования нет. Если центр виджета не попал в ячейку, но его область пересекает таблицу, виджет смещается за ближайший край таблицы.

Колбэки EEL2

Иллюстрация. Инспектор текстового поля. Сверху — базовые флаги, ниже — события колбэков, затем поле с кодом EEL2.

10. Примитивы рисования

Иллюстрация. Примитивы на холсте. Прямоугольник, круг, треугольник, линия, текст и дуга. Все примитивы экспортируются вызовами draw list и располагаются под слоем виджетов.

Чтобы нарисовать фигуру, выберите инструмент в палитре и протяните указатель по холсту. Полигон строится иначе: задавайте вершины щелчками. Замкните фигуру повторным щелчком по первой точке, двойным щелчком или клавишей Enter. Клавиша Esc отменяет незавершённый полигон.

Примитив Параметры Экспорт
Прямоугольник fill, stroke, rounding, thickness, opacity AddRectFilled и AddRect
Круг fill, stroke, thickness, opacity AddCircle(Filled); AddEllipse(Filled) при W ≠ H
Треугольник fill, stroke, thickness, orient (четыре направления) AddTriangle(Filled)
Линия stroke, thickness AddLine
Полигон fill, stroke, thickness, список точек PathFillConvex для выпуклых многоугольников; триангуляция с AddTriangleFilled для вогнутых
Дуга ring — stroke, thickness, начальный и конечный угол; pie — то же плюс fill PathArcTo и PathStroke; у pie дополнительно PathFillConvex
Текст текст, цвет, размер, выравнивание по горизонтали и вертикали AddText, при необходимости с CalcTextSize

Иллюстрация. Инспектор дуги. Углы задаются в градусах по правилам ImGui: 0° соответствует направлению вправо, значения растут по часовой стрелке. Развёртка 270° с началом в 135° соответствует стандартной шкале поворотной ручки.

Рисунки при экспорте обрезаются по макету и попадают в код, если хотя бы пересекают его: прямоугольник, частично выходящий за край, будет выведен, а выходящую часть обрежет ImGui. Для виджетов правило строже — виджет должен целиком находиться внутри фрейма, иначе он не экспортируется.

Размер рисованного текста. Поле text size меняет текст на холсте Builder. Экспортируемый вызов AddText для текстового примитива не передаёт этот размер и использует текущий размер шрифта ImGui. Если в экспорте нужен определённый размер текста, задайте шрифт в Lua.

Заливка, обводка и их связь

У примитивов раздел fill & stroke инспектора содержит два образца цвета, по флажку none у каждого и кронштейн-связку слева.

Флажки none — взаимоисключающая пара: фигура может остаться без одной краски, но не без обеих. Снятыми могут быть оба, поставленными оба — нет. Пока один стоит, второй показан приглушённо; щелчок по приглушённому переносит none на него одним действием, и весь перенос — один шаг отмены.

none у обводки предлагается только у замкнутых фигур, у которых есть заливка: прямоугольник, круг, треугольник, полигон и дуга в режиме pie. У линии обводка — единственная краска, у дуги в режиме ring обводка и есть сама фигура, поэтому там флажок не показывается.

Связка — кронштейн слева от двух рядов. Пока она замкнута, выбор цвета в любом из рядов записывает оба, одним шагом отмены. Включение связки само по себе ничего не перекрашивает: это указание на то, что будет дальше. У линии и у дуги в режиме ring, где вторая краска отсутствует, связка не показывается.

Обратите внимание. ImGui заливает только выпуклые пути. Невыпуклый полигон при экспорте триангулируется: вместо заливки выводится набор вызовов AddTriangleFilled. Контур при этом остаётся одним замкнутым путём.

11. Настройки холста и проекта

Заголовок окна

Название, под которым макет откроется в REAPER, показано в синей шапке над холстом. Щёлкните по нему — строка станет полем ввода. Enter применяет название, Esc отменяет правку.

Заголовок попадает в сгенерированный скрипт (CreateContext и ImGui_Begin), сохраняется в файле проекта и задаёт имя скачиваемого файла: Track Tools → Track_Tools.lua. Апостроф в названии экранируется, поэтому скрипт остаётся работоспособным.

Размер

Поля W и H на вкладке Canvas задают размер содержимого окна плагина. Эти значения передаются в экспорт как W, H. Чтобы применить их, нажмите Enter или уберите фокус с поля. Тот же результат даёт перетаскивание маркера ⇲.

Фон

  • Default. Холст отображается в цветах активной темы, а в экспорте сохраняется собственный фон окна ImGui. Если выбрана тема, отличная от Default, Builder дополнительно применяет её цвет фона к дочернему окну холста через PushStyleColor.
  • Custom. Выберите цвет и непрозрачность в палитре Canvas. Непрозрачность смешивает выбранный цвет с белым; экспорт записывает полученный непрозрачный цвет как Col_WindowBg. Окно REAPER прозрачным не становится.

Окно выбора цвета

Цветовые образцы рисунков, переопределений StyleRegion, группового редактирования и редактора тем открывают всплывающую палитру Builder. Обычно она располагается справа и выше; у края окна смещается влево или вниз. На вкладке Canvas используется отдельная встроенная палитра фона.

Всплывающая палитра содержит поле насыщенности и яркости, полосу оттенка, поле HEX и недавние цвета. Экранная пипетка появляется только при поддержке браузером. При открытии фокус получает HEX; поддерживаются #RRGGBB и #RGB. Цвет применяется сразу. Enter закрывает палитру; Esc закрывает её и возвращает фокус, не отменяя изменения. Объединение изменений в истории зависит от редактируемого поля.

Недавние образцы общие для всех цветовых полей и хранятся до перезагрузки страницы.

Сетка

Флажок Show grid включает отображение тонкой сетки; настройка сохраняется отдельно для режимов Editor и Preview. Параметр Step задаёт шаг сетки — 2, 5 или 10 px. Этот же шаг используется для привязки.

Audit grid

Команда View → Reference grid in export включает пурпурную измерительную сетку с шагом 50 px. В отличие от обычной сетки, audit grid попадает в экспорт: в генерируемый код добавляется блок, который рисует ту же сетку в окне REAPER. Так можно проверить соответствие координат в Builder и в окне REAPER. Перед выпуском скрипта отключите эту команду.

Масштаб и панорамирование

Масштаб изменяется от 75% до 250%. Готовые значения доступны в статусной строке, сочетание Cmd/Ctrl + колесо мыши масштабирует относительно курсора, кнопка ⤢ вписывает макет в окно. Панорамирование выполняется инструментом Hand или при удержании клавиши Space. Масштаб влияет только на отображение, координаты объектов при этом не меняются.

12. Темы

Иллюстрация. Выбор темы. Встроенные и пользовательские темы, ниже — кнопки + Add и Edit . Активная тема сохраняется в проекте.

Тема определяет пятнадцать цветовых значений: тринадцать цветов стиля ImGui, фон дочернего окна и цвет подписей в draw list. В комплект входят Default (без переопределений цветов темы), Slate (dark) и Light.

Тема действует в двух местах: на отрисовку холста в режиме Preview и на экспорт. Тема, отличная от Default, выводит свои цвета вызовами PushStyleColor сразу после открытия дочернего окна-холста и снимает их перед его закрытием.

Иллюстрация. Тема Slate в режиме Preview. Предпросмотр приближённо показывает вид макета в REAPER с палитрой этой темы.

Пользовательские темы

Иллюстрация. Окно New Theme. Четыре цвета задают всю палитру; полоса образцов показывает производные слоты.

Чтобы создать тему, задайте четыре цвета: фон, текст, элементы управления и акцент. Остальные одиннадцать слотов вычисляются автоматически. Состояния hovered и active получаются сдвигом от цвета элементов управления — светлее на тёмном фоне и темнее на светлом. Цвета заголовков смешиваются из фона и акцента. Акцентный цвет используется для галочек и активного ползунка.

  • Пользовательские темы хранятся в localStorage браузера и доступны только на этом компьютере и в этом браузере.
  • Определение активной пользовательской темы включается в файл проекта. После загрузки проекта тема доступна в текущем сеансе; она не добавляется автоматически в постоянную библиотеку тем браузера.
  • Кнопка Edit включает режим управления пользовательскими темами: тему можно открыть для изменения кнопкой с карандашом или удалить. Встроенные темы изменять и удалять нельзя.

13. Режим Preview

Иллюстрация. Режим Preview. Метки имён, заголовки контейнеров и элементы выделения не выводятся. Виджеты отображаются приближённо к своему виду в ImGui с учётом активной темы.

Используйте переключатель Editor / Preview над холстом. Preview запрещает прямое перетаскивание, изменение размеров и размещение на холсте, но не блокирует проект: инспектор и команды редактирования остаются активными. Виджеты рисуются приблизительно; щелчок выделяет их, а не выполняет действие экспортированного элемента управления. Переключайте вкладки в режиме Editor.

Часть виджетов отображается схематично — штрихованными рамками с именем: Group, Table, ColorPicker3/4 и TextWrapped. Если такие виджеты есть на холсте, внизу выводится баннер.

Ограничения Preview в 1.0.3:

  • ColorEdit не учитывает флаги отображения. Виджет всегда выводит R/G/B и образец цвета независимо от значений DisplayHSV, Hex и NoInputs.

В Preview и экспорте переопределение цвета текста StyleRegion действует и на внешние подписи. Другие свойства виджетов могут отображаться схематично: Preview не запускает ReaImGui и не выполняет сгенерированный Lua.

ProgressBar в Preview имеет фиксированное заполнение примерно 45% и не показывает экспортируемую анимацию или overlay. Числовые элементы также используют примерные значения, не выполняя сгенерированный скрипт.

14. Экспорт

Проверка перед экспортом

В верхней части окна Export расположена панель проверки. Она запускается при каждом открытии окна и делит найденное на три уровня.

  • Ошибка. Проверка обнаружила условие, блокирующее экспорт: например, некорректные ID, родительские связи, геометрию, типы виджетов или числовые значения. Кнопки copy и download недоступны до устранения ошибок. Проверяются данные проекта; Lua не выполняется.
  • Предупреждение. Экспорт доступен, но настройка или пропуск элемента требуют внимания. Примеры: объекты вне макета, потомки исключённых контейнеров, обрезанные рисунки, совпадающие имена, одинаковые значения радиокнопок, пустой TabBar или отсутствующие ячейки таблицы.
  • Информация. Одна строка со счётчиком: сколько элементов не имеют видимой подписи.

Заголовок панели сообщает главное — сколько объектов не попадёт в экспорт, и сколько попадёт из общего числа. Именно этого сам экспорт никогда не показывает.

Щелчок по строке проверки выделяет соответствующий объект на холсте.

Иллюстрация. Окно Export, вкладка ReaImGui. Готовый к запуску скрипт: создание контекста, константы позиций, переменные состояния, функция отрисовки и цикл defer. Кнопка copy копирует код в буфер обмена.

Структура генерируемого файла

Код всегда имеет одинаковую структуру:

  1. Заголовочные комментарии. Размер холста и правила размещения.
  2. Контекст и размеры. Вызов CreateContext, значения W, H и OUTER_H. Последнее добавляет высоту полосы заголовка, чтобы область содержимого совпадала с размерами макета.
  3. Константы положения. Координаты X/Y и ширины виджетов перечислены в начале файла. Экспортёр также вставляет координаты и размеры непосредственно во многие вызовы draw list и виджетов. Для согласованного изменения макета отредактируйте проект Builder и экспортируйте заново.
  4. Переменные состояния. По одной переменной на виджет с состоянием, по одной на группу радиокнопок, а также массивы reaper.new_array для семейств с суффиксом N.
  5. Шрифты и колбэки EEL2. Создаются и прикрепляются один раз, до цикла, если их использует хотя бы одна StyleRegion или поле ввода.
  6. Функция draw(). Задаёт нулевые padding и spacing, открывает окно, получает draw list и точку отсчёта, открывает дочернее окно-холст, применяет тему, выводит рисунки, затем виджеты в порядке дерева.
  7. Цикл defer.

Правила размещения в коде

PushStyleVar(StyleVar_WindowPadding, 0, 0)
PushStyleVar(StyleVar_ItemSpacing,   0, 0)
…
local wx, wy = GetWindowPos(ctx)
local cx, cy = GetCursorStartPos(ctx)
local ox, oy = wx + cx, wy + cy   -- точка отсчёта для всех координат
…
SetCursorScreenPos(ctx, ox + SLIDER_4_X, oy + SLIDER_4_Y)
SetNextItemWidth(ctx, SLIDER_4_W)

Виджеты и геометрия draw list отсчитываются от одной точки ox, oy. Поэтому прямоугольник, нарисованный за кнопкой, останется за ней и во время работы плагина.

Важно. Нулевые значения padding и spacing определяют всю раскладку. Если добавить в готовый код обычные потоковые виджеты, не задав позицию курсора, они будут выведены без отступов. Задавайте позицию курсора самостоятельно или восстанавливайте стилевые переменные вокруг добавленного фрагмента.

Состав экспорта

  • Виджет экспортируется, только если целиком находится внутри границ макета. Проверка выполняется по полной занятой области виджета. Виджет, выходящий за край, в код не попадает.
  • Рисунок экспортируется, если пересекает границы макета.
  • Audit grid экспортируется, если включена.

15. Сохранение и загрузка

Автосохранение и восстановление

Builder сам сохраняет черновик текущего макета в память браузера. Запись происходит через 0,8 с после изменения; кроме того, дважды в секунду выполняется проверка на изменения, прошедшие мимо истории.

Состояние показано в статусной строке: No unsaved changes, Unsaved changes, Saving…, Autosaved ЧЧ:ММ.

Если при открытии Builder найден черновик, предлагается восстановить или удалить его. Это возможно как после обычного закрытия, так и после сбоя. Диалог показывает время черновика, число элементов и версию Builder. Работа хранилища для локальных файлов зависит от браузера, поэтому сохраняйте переносимую копию JSON.

Builder удаляет черновик при запуске скачивания JSON, успешной загрузке проекта или выполнении New Project. Он не может подтвердить, что браузер завершил сохранение скачанного файла. Отмена выбора загружаемого файла или ошибка загрузки сохраняет черновик. Восстановленный черновик считается несохранённым до запуска скачивания проекта.

Автосохранение не заменяет файл проекта: оно живёт в одном браузере и исчезает вместе с данными сайта.

File → Save Project скачивает reaper-ui-project.json. В него входят заголовок, размеры холста, фон, активная тема и её пользовательское определение, состояние audit grid, привязка, шаг сетки, счётчики и объекты. Режим Editor/Preview, видимость обычной сетки, масштаб и история отмены в файл не записываются.

Команда File → Load Project заменяет текущий макет. Если в текущем проекте есть несохранённые изменения, перед выбором файла запрашивается подтверждение; при отсутствии таких изменений диалог выбора файла открывается сразу. После успешной загрузки история изменений очищается, а масштаб возвращается к 100%. Builder нормализует загруженный файл по тем же правилам, что и данные при запуске. Поэтому проекты из старых сборок могут быть приведены к актуальной структуре автоматически.

Файл с отсутствующими или повторяющимися идентификаторами объектов отклоняется до замены текущего макета. При такой ошибке открытый проект остаётся без изменений.

Команда File → New Project удаляет все объекты и возвращает размер холста к 600 × 400 px. Заголовок окна, фон, тема, сетка и привязка при этом сохраняют текущие значения.

Обратите внимание. Файл проекта — единственный формат, сохраняющий данные без потерь. Экспортированный код на Lua обратно в Builder не загружается. Храните файл .json вместе со скриптом.

17. Ограничения сборки

В разделе перечислено, что версия 1.0.3 не выполняет или выполняет не так, как можно ожидать.

Не реализовано

  • Редактирование списков Combo и ListBox. В экспорт выводятся пять элементов-заглушек. Сами виджеты рабочие: переменная выбора объявляется и обновляется — заменить нужно только строки элементов. В сгенерированном коде место отмечено комментарием -- TODO: replace the placeholder items ….
  • Импорт и экспорт темы отдельным файлом. Тема хранится в файле проекта и в localStorage.

Особенности поведения

  • Предварительная настройка виджета. В форме до размещения отображаются поля min, max, format, числовые флаги, components, tooltip и bullet, но в версии 1.0.3 их значения не переносятся в созданный виджет. Задавайте эти параметры после размещения; подробнее см. §5.1.
  • Виджет, выходящий за край макета, не экспортируется. Панель проверки в окне Export называет такие объекты поимённо — см. §14. Вместе с контейнером из экспорта выпадает и всё его содержимое, даже если сами дочерние объекты находятся внутри макета.
  • Подписи слайдеров, полей ввода и подобных виджетов располагаются над виджетом и вне его области. Без вертикального зазора они накладываются на объекты выше.
  • Имя файла .lua берётся из заголовка окна. Символы, кроме латинских букв, цифр, подчёркивания и дефиса, заменяются подчёркиваниями; если подходящего имени не осталось, используется MyPlugin.lua.
  • Второй ряд верхней панели пуст, пока не открыта категория виджетов. При запуске открыта категория Display.
  • Панель выбора темы в узком окне может перекрывать часть макета. Чтобы закрыть её, щёлкните за пределами панели.
  • Пользовательские темы хранятся в localStorage одного браузера и удаляются вместе с данными сайта. Постоянная копия темы — файл проекта.

При правке готового кода учитывайте три особенности.

  • Размещаемые пользователем виджеты получают абсолютные позиции курсора; структурными TabItem и TableCell управляют родители. Координаты и размеры встречаются и непосредственно в вызовах, поэтому правка только констант в начале файла не обновляет весь макет.
  • Виджеты с внешней подписью помещены в блок do … end: подпись выводится в draw list, а виджет использует скрытый идентификатор вида ##Name.
  • Контейнеры вкладываются в том же порядке, что и на холсте, и каждый закрывается собственным вызовом End…. Самый внешний EndChild относится к холсту.
