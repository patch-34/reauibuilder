<a name="manual-reaper-ui-builder"></a>

# ReaUI Builder

Визуальный редактор макетов для интерфейсов ReaImGui.

Создайте макет окна на холсте, а Builder сгенерирует Lua-код для ReaImGui: вызовы виджетов, геометрию draw list и настройки стилей. Координаты в макете логические — изменение масштаба меняет только отображение на холсте, а не экспортируемые значения. Preview приблизительно показывает, как интерфейс будет выглядеть в работающем плагине.

Это руководство относится к версии **1.0.70**. В нём описаны актуальные функции и рабочий процесс; устаревшие способы работы не рассматриваются.

---

<a name="manual-01-назначение"></a>

## 01. Назначение

ReaUI Builder запускается из локального HTML-файла и не требует установки, сервера или сборки. Стили, иконки, контракты виджетов и генератор кода встроены в этот файл. Редактировать макеты и генерировать код можно без подключения к сети.

Далее в этом руководстве ReaUI Builder называется просто **Builder**.

Builder предназначен для создания **макета интерфейса**, а не логики скрипта. В нём можно задать положение и размер виджетов, их подписи и основные параметры, а затем экспортировать структуру окна в Lua.

Builder не создаёт DSP, логику проекта и обработку событий. Для интерактивных виджетов в экспортируемом коде оставляются места для пользовательской логики, отмеченные комментариями `-- TODO`.

- **Результат работы:** Lua-код для ReaImGui 0.10 или более поздней версии
- **Виджеты:** 48 размещаемых типов в 41 семействе, а также автоматически управляемые типы TabItem и TableCell
- **Примитивы рисования:** 7 — прямоугольник, круг, полигон, линия, текст, треугольник и дуга
- **Формат проекта:** JSON с номером версии

В основе Builder лежат два принципа.

<a name="manual-абсолютное-размещение"></a>

### Абсолютное размещение

ImGui по умолчанию располагает виджеты последовательно. Builder использует абсолютное позиционирование: `WindowPadding` и `ItemSpacing` устанавливаются в ноль, а перед каждым виджетом задаётся явная позиция курсора.

Так сохраняются заданные координаты макета. Нативные метрики шрифтов и высота элементов управления могут отличаться от браузерного приближения, поэтому перед завершением макета проверьте экспортированный интерфейс в REAPER.

<a name="manual-контракты-виджетов"></a>

### Контракты виджетов

Для каждого типа виджета задан **контракт** — набор правил, определяющих его размер по умолчанию, допустимые изменения размеров, способ применения ширины и положение подписи.

Холст, инспектор и генератор кода используют общие контракты, дополненные правилами для отдельных типов. У Checkbox фиксированы размеры, у Slider фиксирована высота и подпись находится снаружи, а высота ColorPicker вычисляется. Далее объясняются различия между рамкой редактирования и экспортируемым размером.

<a name="manual-02-быстрый-старт"></a>

## 02. Быстрый старт

Откройте HTML-файл в современном браузере. Builder работает локально через `file://`; для редактирования и генерации кода сеть не нужна. Для запуска экспортированного Lua-скрипта требуется REAPER с ReaImGui 0.10 или более поздней версии.

1. Откройте вкладку **Canvas** в правой панели и задайте размер создаваемого окна. По умолчанию используется размер **550 × 400 px**.
2. Выберите виджет в одной из категорий верхней панели. Контейнеры **Group, Style, Table, Header, Tree** и **Tabs** также доступны постоянными ярлыками в левой палитре. Категории: **Buttons & Toggles, Display, Fields, Sliders & Drags, Selection, Color, Layout**.
3. Щёлкните по холсту. Левый верхний угол виджета будет установлен в точку щелчка с учётом привязки к сетке.
4. Настройте выбранный виджет в панели **Selection**: измените подпись, диапазон значений, флаги, координаты и размер.
5. Нажмите **Export**, устраните ошибки проверки и выберите **download .lua**. Либо нажмите **copy** и сохраните код в файл `.lua`. Загрузите файл через окно Actions в REAPER и запустите его.

> **Иллюстрация. Рабочее пространство при запуске.** Слева находится палитра инструментов. В центре — холст с макетом окна и линейками. Справа — контекстная панель **Canvas / Elements / Info** и инспектор **Selection**. Внизу расположена статусная строка.

<p align="center"><img src="screenshots/02__Quick_start.png" alt="Рабочее пространство Builder при запуске, панель виджетов и инспектор видны"></p>

> **Сохраняйте редактируемый проект.** Выберите **File → Save Project** (`Cmd/Ctrl + S`) и храните JSON-файл вместе со скриптом. Черновики браузера доступны через **File → Restore projects…**, но не заменяют файл проекта.

<a name="manual-03-рабочее-пространство"></a>

## 03. Рабочее пространство

В режиме **Editor** над каждым виджетом отображается серая метка с его именем.

Имя таблицы (`⊞ <name>`) и значок замка у **Table** находятся на служебной вкладке **над** рамкой таблицы. Щёлкните по вкладке, чтобы выбрать или перетащить таблицу; в Preview и экспорте она не отображается.

**Panel** показывает в левом верхнем углу бледную пометку `☐ Panel`. Это служебное оформление редактора, которое не занимает места. Щелчок в верхней полосе высотой 24 px выбирает Panel даже поверх дочернего виджета.

Верхняя полоса **TabBar** — это настоящий ряд вкладок, тот же, что рисует REAPER. Щелчок по нему выбирает TabBar.

> **Иллюстрация. Макет в режиме Editor.** Служебные подписи и полосы контейнеров помогают редактировать структуру макета и не являются частью экспортируемого интерфейса.

<a name="manual-31--верхняя-панель-и-меню"></a>

### 3.1 · Верхняя панель и меню

В верхней панели находятся четыре меню, глобальные команды и категории виджетов.

| Меню | Команды |
| --- | --- |
| **File** | New Project · Save Project · Save As… · Restore projects… · Load Project |
| **Edit** | Undo · Redo · Copy · Paste · Delete · Duplicate · Group selection · Ungroup selection · Select All · Deselect All · Clear All |
| **View** | Dark mode · Grid · Snap to grid · Reference grid in export · Hide widget names · Hide draw objects names · Widget footprints · Panels · Zoom to fit · Actual size (100%) |
| **Help** | User Manual ↗ · Keyboard Shortcuts · Report a Bug… · About |

**Undo** и **Redo** недоступны, если соответствующая история действий пуста.

**Reference grid in export** включает пурпурную измерительную сетку с шагом 50 px. В отличие от обычной сетки, она также попадает в экспорт. На вкладке Canvas эта же настройка называется **Audit grid**.

**Snap to grid** включает и отключает привязку к сетке. Активные пункты меню **View** отмечены галочкой.

**Hide widget names** и **Hide draw objects names** независимо скрывают служебные метки имён, но не видимый текст интерфейса. Подменю **Panels** управляет панелями Canvas, Elements, Info, Selection и Tools и позволяет вернуть скрытую панель. Их видимость запоминается в текущем браузере отдельно от проекта.

Команда **Clear All** удаляет все элементы с холста после подтверждения.

Кнопка **Export** открывает окно со сгенерированным кодом.

**User Manual ↗** открывает это руководство в новой вкладке браузера.

> **Report a Bug…** открывает диалог для отправки отчёта по почте. В нём собраны последние 50 записей журнала действий, номер сборки и текущий размер окна — Builder складывает их в готовый текст отчёта, который можно просмотреть перед отправкой. Опишите, что произошло, при необходимости отметьте **Include my layout**, чтобы приложить весь проект, затем щёлкните по адресу почты, чтобы скопировать его, и вставьте отчёт в письмо. Пока вы сами не отправите письмо, ничего никуда не уходит.

Справа расположены семь категорий виджетов. Щёлкните по категории, чтобы открыть панель с входящими в неё виджетами. Повторный щелчок закрывает панель.

<a name="manual-32--панель-виджетов"></a>

### 3.2 · Панель виджетов

Панель содержит полный список виджетов, разделённый на семь категорий.

Чтобы добавить виджет, откройте нужную категорию, выберите его, а затем щёлкните по холсту.

Если содержимое категории не помещается по ширине, панель можно прокручивать горизонтально колесом мыши.

При запуске открыта категория **Display**. Повторный щелчок по кнопке закрывает её. Если ни одна категория не открыта, панель остаётся пустой — это штатное поведение.

<a name="manual-33--левая-палитра"></a>

### 3.3 · Левая палитра

В левой палитре находятся постоянные инструменты:

- **Select**, **Hand** и **Zoom**;
- семь инструментов рисования;
- ярлыки шести контейнеров: Group, StyleRegion, Table, CollapsingHeader, TreeNode и TabBar.

**Select** — инструмент по умолчанию. После размещения объекта Builder автоматически возвращается к нему.

**Hand** используется для панорамирования рабочей области. Для временного включения Hand удерживайте `Space` до начала перетаскивания, затем отпустите клавишу, чтобы вернуться к прежнему инструменту. Если объект уже перемещается, изменяет размер или рисуется, Space не запускает второй жест.

Инструмент **Zoom** увеличивает масштаб щелчком вокруг выбранной точки; `Alt/Option + щелчок` уменьшает масштаб. `Esc` возвращает Select.

Инструменты рисования по умолчанию работают однократно: после создания фигуры снова включается **Select**.

Чтобы нарисовать несколько прямоугольников, окружностей, линий, треугольников или дуг, выберите инструмент, удерживая `Shift`, а перед рисованием отпустите клавишу. Инструмент остаётся активным до выбора другого инструмента или нажатия `Esc`; в статусной строке появляется `[sticky]`. После создания Polygon, Text или виджета снова включается Select.

<a name="manual-34--область-холста"></a>

### 3.4 · Область холста

В центральной части рабочего пространства отображается макет окна скрипта: заголовок **MyPlugin**, область будущего интерфейса и рабочее пространство вокруг неё.

Размер области макета соответствует размеру экспорта. Заголовок служит напоминанием о собственной полосе заголовка ImGui; её высота учитывается в экспортируемом коде:

`OUTER_H = H + высота заголовка`

Над холстом и вокруг него расположены дополнительные элементы управления:

- **Editor / Preview** — переключатель режима отображения в верхней центральной части. Подробнее см. §13.
- **Theme** — выбор темы справа над холстом. Подробнее см. §12.
- **Линейки** — расположены сверху и слева и показывают координаты макета с учётом текущего масштаба.
- **Маркер изменения размера ⇲** — расположен в правом нижнем углу макета. Перетащите его, чтобы изменить размер холста. Это эквивалентно изменению `W` и `H` на вкладке **Canvas**.
- **Баннер Preview** — появляется в режиме Preview, если макет содержит виджеты, которые Builder может показать только схематично.

<a name="manual-35--правая-панель"></a>

### 3.5 · Правая панель

Правая панель состоит из двух частей: контекстной панели **Canvas / Elements / Info** и инспектора **Selection**. Стрелка в заголовке сворачивает или разворачивает верхнюю панель, оставляя вкладки на месте. При выборе объекта Canvas сворачивается, освобождая место для Selection; щелчок по вкладке снова раскрывает её. Стрелка под Elements увеличивает список за счёт высоты Selection. Видимость панелей настраивается через **View → Panels**.

<a name="manual-info"></a>

#### Info

Когда выбран виджет или активирован инструмент его размещения, вкладка **Info** показывает приблизительный внешний вид виджета в ImGui и краткое описание его назначения. Выбор виджета в панели или левой палитре автоматически открывает Info; после размещения вкладка остаётся открытой и показывает созданный объект.

Info показывает один выбранный виджет или рисунок либо активный инструмент. Если такого контекста нет, здесь отображается сводная информация о проекте.

<a name="manual-elements"></a>

#### Elements

Вкладка **Elements** показывает рисунки, виджеты, контейнеры и группы редактора в виде дерева. Дочерние виджеты отображаются с отступом под контейнерами.

- Щелчок по строке объекта выбирает его. Для участника группы это индивидуальное выделение с его собственными свойствами.
- Щелчок по заголовку группы выбирает всю группу. Кнопка **Select group** в Selection также возвращает от отдельного участника к группе.
- `Cmd/Ctrl + щелчок` добавляет или убирает отдельную строку, `Shift + щелчок` выбирает диапазон.
- Когда список в фокусе, `↑/↓` выбирают соседние строки, а `Home/End` — первую или последнюю; Shift расширяет выделение. Эти клавиши перемещаются по списку и не двигают объекты.
- `Enter` переносит фокус на холст, сохраняя выделение. После этого стрелки перемещают выбранные объекты.

Перетаскивание строк меняет порядок наложения: **чем выше строка, тем ближе объект к переднему плану**. Менять порядок можно только среди объектов одного родителя и одного слоя. Рисунки остаются ниже виджетов, группа перемещается единым блоком, а структурные ячейки Table таким способом не переставляются. Изменение порядка поддерживает Undo.

Щелчок правой кнопкой открывает команды Rename, Copy, Cut, Delete, Group/Ungroup и **Color → Select color / Surprise me**. Строка участника относится к нему, заголовок группы — ко всей группе.

<a name="manual-canvas"></a>

#### Canvas

На вкладке **Canvas** находятся параметры самого макета: размер окна, режим фона, видимость сетки и её шаг.

Здесь же расположен выбор цвета фона с пипеткой, недавними образцами и настройкой прозрачности. Код цвета показан в нижней строке вкладки и меняется прямо во время выбора; в режиме **Custom** его можно ввести вручную, а в режиме **Default** там показано название темы, цвет которой использует холст.

Заголовок окна редактируется не здесь, а на самом макете: щёлкните по названию в шапке холста — см. §11.

<a name="manual-selection"></a>

#### Selection

Инспектор **Selection** формируется по контракту выбранного виджета. В нём отображаются только те параметры, которые применимы к этому типу.

Поэтому набор полей меняется при выборе разных виджетов: у простых элементов отображается только несколько основных параметров, а у виджетов с диапазонами, форматированием или дополнительными флагами инспектор заметно больше.

Поля инспектора сгруппированы в разделы: **Main** — подпись, имя, значения и диапазоны; **Structure** — вкладки и таблицы; **Appearance** — цвета, скругления и толщина; **Advanced** — форматы и флаги. Затем идут геометрические поля. Для рисунков **Primitive order** предшествует **Size**, а **Position** становится последним блоком свойств перед Delete. Пустые разделы скрыты.

Если выделено несколько объектов, инспектор переключается в режим пакетного редактирования — см. §5.6.

Все параметры инспектора описаны в §8. Полный список параметров для каждого типа виджета приведён в приложении B.

<a name="manual-36--статусная-строка"></a>

### 3.6 · Статусная строка

В статусной строке отображаются:

- текущий масштаб и кнопка вписывания макета в окно;
- активный инструмент и подсказка по его использованию;
- координаты курсора;
- `X`, `Y`, `W` и `H` текущего выделения;
- состояние привязки к сетке;
- количество элементов.

Эта же область используется для служебных сообщений.

Если Builder отклоняет размещение, вместо отдельного диалогового окна в статусной строке ненадолго появляется сообщение, например:

`blocked: overlaps existing widget`

или

`blocked: container too large for target`

<a name="manual-04-основные-понятия"></a>

## 04. Основные понятия

<a name="manual-41--виджеты-и-рисунки"></a>

### 4.1 · Виджеты и рисунки

Объекты на холсте делятся на два типа: **виджеты** и **рисунки**. Они различаются по интерактивности, вложенности, правилам перекрытия, порядку отрисовки и способу экспорта.

|  | Виджеты | Рисунки |
| --- | --- | --- |
| **Что это** | Элементы управления и отображения ImGui: кнопки, слайдеры, таблицы, текст и другие виджеты | Геометрия в draw list окна |
| **Интерактивность** | Элементы управления интерактивны; виджеты Display служат для отображения | Нет; рисунки используются для оформления |
| **Экспорт** | `ImGui_Button`, `ImGui_SliderDouble`, … | `DrawList_AddRect`, `AddCircle`, … |
| **Перекрытие** | Предотвращается проверками размещения; исключения описаны в §4.7 | Допускается; учитывается порядок наложения |
| **Вложенность** | Допускается внутри контейнеров | Не поддерживается |
| **Отрисовка** | Поверх рисунков | Под всеми виджетами |

Рисунки подходят для элементов, которым не соответствует отдельный виджет ImGui: например, для корпуса индикатора, рамки секции, дуги шкалы или логотипа.

Используйте виджеты для элементов управления и отображения, которые предоставляет ImGui.

<a name="manual-42--семейства-и-варианты"></a>

### 4.2 · Семейства и варианты

Палитра Builder организована по **семействам**, а экспортируемый код — по конкретным **типам виджетов**.

Семейство объединяет варианты одного элемента управления. Например:

- `Slider` → `SliderInt` / `SliderDouble` — по умолчанию Double
- `Drag` → `DragInt` / `DragDouble` — по умолчанию Double
- `Input` → `InputInt` / `InputDouble` — по умолчанию Double
- `VSlider` → `VSliderInt` / `VSliderDouble` — по умолчанию Double
- `DragRange` → `DragIntRange2` / `DragFloatRange2` — по умолчанию Double
- `ColorEdit` → `ColorEdit3` / `ColorEdit4` — по умолчанию RGB
- `ColorPicker` → `ColorPicker3` / `ColorPicker4` — по умолчанию RGB

Если у семейства есть несколько вариантов, в верхней части инспектора появляется строка **variant**. Выберите вариант до размещения, пока активен инструмент. У уже созданного виджета строка показывает текущий вариант, но недоступна для изменения. Для другого варианта удалите виджет и разместите его заново.

Не смешивайте имя семейства в палитре и конкретный тип в коде: например, **Slider** — семейство в Builder, а **SliderDouble** — тип в экспортированном коде.

Некоторые подписи палитры короче названий контрактов: **Hint** = HelpMarker, **RadioButton** = RadioButtonEx, **TextLink** = TextLinkOpenURL, **Multiline** = InputTextMultiline, **Style** = StyleRegion, **Header** = CollapsingHeader, **Tree** = TreeNode, **Tabs** = TabBar.

<a name="manual-43--координаты-и-привязка"></a>

### 4.3 · Координаты и привязка

Координаты `x` и `y` каждого вложенного объекта хранятся **относительно его родителя**.

Например, кнопка в левом верхнем углу панели может хранить координаты `(4, 28)`, хотя сама панель расположена так, что абсолютная позиция кнопки на макете равна `(24, 278)`.

При перемещении панели кнопка перемещается вместе с ней, а её собственные координаты `(4, 28)` не изменяются.

Инспектор показывает **абсолютные координаты макета** и автоматически переводит их в хранимые координаты относительно родителя. Экспортёр воспроизводит размещение абсолютными координатами там, где это уместно, и локальной точкой отсчёта внутри исполняемых контейнеров, например ячеек таблицы.

<a name="manual-привязка-к-сетке"></a>

#### Привязка к сетке

При включённой привязке координаты округляются до выбранного шага сетки.

Шаг задаётся на вкладке **Canvas**:

- 2 px
- 5 px
- 10 px — значение по умолчанию

Привязка действует при размещении, перемещении и изменении размера объектов.

Чтобы отключить её, выберите **View → Snap to grid**. Текущее состояние отображается в статусной строке.

> **Примечание — шаг сетки и крупная сетка.** Выбранный шаг определяет привязку и расстояние между тонкими линиями сетки. Толстые линии с шагом 50 px постоянны и служат только визуальным ориентиром. Привязка к ним не выполняется. При сильном уменьшении масштаба Builder может отображать сетку с более крупным визуальным шагом, но координаты по-прежнему привязываются к значению, выбранному в **Canvas**.

<a name="manual-44--контракты-размеров"></a>

### 4.4 · Контракты размеров

ImGui не позволяет независимо задавать ширину и высоту для всех типов виджетов. Builder воспроизводит эти ограничения на холсте, чтобы макет можно было корректно перенести в код.

Для высоты используются четыре режима:

| Режим | Поведение |
| --- | --- |
| `explicit-size` | Контракт имеет явную рамку макета. Button, Panel и подобные элементы передают размеры в ImGui; некоторые типы вместо этого используют вычисляемую высоту или пересчёт в число строк. |
| `native-fixed` | Высоту определяет ImGui: обычно это одна высота фрейма, около 20 px. Так работает большинство виджетов ввода. |
| `native-content` | Высота определяется содержимым, например текстом. |
| `native-line` | Высота соответствует одной разделительной линии. |

Для виджета с фиксированной высотой остаются только боковые маркеры, если ширину можно менять, а **H** недоступно. Checkbox, ArrowButton, SmallButton и RadioButtonEx не имеют маркеров размера; ширина SmallButton и RadioButtonEx следует за подписью. У ColorPicker есть только боковые маркеры, а высота вычисляется из ширины и флагов.

Под полем появляется `↑ height fixed by ImGui` или `↑ size fixed by ImGui`. Там, где контракт разрешает, ширину всё равно можно менять.

**ColorPicker.** Новый элемент имеет ширину 200 px и включённый **NoSidePrev**; Builder резервирует высоту 246 px. Поле H доступно только для чтения и меняется вместе с шириной и флагами. Включение бокового предпросмотра добавляет 60 px к занимаемой ширине, не меняя ширину самого элемента выбора цвета. Экспорт передаёт в `SetNextItemWidth` ширину элемента без бокового предпросмотра, а не всю зарезервированную область.

**ListBox.** Экспортёр превращает H в число видимых строк: `max(2, round(H / 18))`; пиксельная высота напрямую не передаётся. TextWrapped также имеет рамку макета в Builder, но итоговую высоту текста определяет ImGui.

Для ширины используются четыре режима:

- `explicit-size` — ширина передаётся непосредственно в вызов виджета;
- `next-item-width` — перед вызовом используется `SetNextItemWidth`;
- `content-or-widget-box` — область на холсте резервирует место под содержимое, а фактический размер рассчитывает ImGui.
- `widget-box-preview` — сохранённая рамка резервирует место в Builder; Checkbox и RadioButtonEx используют нативный размер в экспортированном интерфейсе.

<a name="manual-45--подписи"></a>

### 4.5 · Подписи

По умолчанию ImGui выводит подпись рядом с виджетом в рамках того же вызова. При абсолютном размещении это может приводить к тому, что текст оказывается за пределами области, заданной в Builder.

Builder в основном использует два описанных ниже способа. Виджеты Display рисуют текст как содержимое, а LabelText размещает подпись справа от значения.

<a name="manual-встроенная-подпись"></a>

#### Встроенная подпись

Используется у **Button, SmallButton, Selectable, RadioButtonEx** и нативных заголовков контейнеров или вкладок. **Group** имеет отдельно нарисованную видимую подпись, а **StyleRegion** не имеет видимого заголовка в экспорте.

Текст передаётся непосредственно в вызов ImGui и отображается как часть виджета.

<a name="manual-внешняя-подпись"></a>

#### Внешняя подпись

Используется у слайдеров, полей ввода, Combo, Checkbox, цветовых и некоторых других виджетов.

Сам виджет получает скрытый идентификатор, например:

`"##Slider_4"`

Видимая подпись выводится отдельно через draw list над верхней границей виджета. На холсте Builder показывает её в том же положении.

Для такой подписи требуется **12 px** дополнительного пространства по вертикали. Оно не входит в собственную область виджета.

Оставляйте место и для подписи, и для корпуса элемента. Проверка занимаемой области (footprint) учитывает подпись сверху, поэтому доступный зазор может быть меньше расстояния между рамками двух элементов.

<a name="manual-46--контейнеры-и-вложенность"></a>

### 4.6 · Контейнеры и вложенность

Builder поддерживает семь типов контейнеров:

- Panel
- Group
- StyleRegion
- CollapsingHeader
- TreeNode
- TabBar
- Table

Кроме того, используются **TabItem** и **TableCell**. Builder создаёт их автоматически; вручную разместить эти элементы нельзя.

Вложенность определяется положением элементов на холсте.

Если разместить виджет внутри рабочей области контейнера, он становится его дочерним элементом. Если вынести его за пределы контейнера, он возвращается на уровень макета или становится дочерним элементом другого подходящего контейнера.

Отдельной команды «добавить в контейнер» нет. Перемещение контейнера также может захватить подходящие виджеты, полностью попавшие в его рабочую область. Щёлкните по значку замка, чтобы разблокировать контейнер на следующее перемещение: существующие дочерние элементы останутся на месте, а захват не выполняется. То же действие можно вызвать, удерживая **U до начала перетаскивания контейнера**.

Не путайте вложенность с **Edit → Group selection**: группа редактора помогает выбирать и перемещать объекты, но не создаёт родительский контейнер. См. §5.7.

**Group, StyleRegion, CollapsingHeader, TreeNode** и **TabBar** резервируют сверху полосу высотой **24 px** для заголовка или служебных элементов редактора. Координаты дочерних элементов учитывают это пространство. Служебная часть полосы не экспортируется; нативные заголовки и вкладки рисует ImGui.

**Panel** использует всю свою рамку: пометка `☐ Panel` не занимает места. Служебная вкладка **Table** находится над рамкой и также не уменьшает рабочую область таблицы; внутри неё резервируется только полоса заголовков столбцов высотой 18 px, если включён **header row**. Автоматически создаваемые TabItem и TableCell не резервируют дополнительную полосу.

При изменении размера контейнера Builder сдвигает дочерние элементы к его рабочей области. Ячейки таблицы и страницы вкладок следуют за размером родителя. Оставляйте достаточно места: перемещение содержимого не уменьшает его размеры, а проверки ручек холста и полей инспектора могут отличаться.

Контейнеры можно вкладывать друг в друга. Например:

`TabBar → TabItem → Panel → Button`

В экспортируемом коде соответствующие вызовы ImGui будут вложены в том же порядке.

Цепочка родителей выбранного виджета отображается в строке **parent** инспектора.

<a name="manual-47--запрет-перекрытия"></a>

### 4.7 · Запрет перекрытия

Builder проверяет размещение и перемещение по полной занимаемой области — **footprint**. Она может выходить за рамку W/H в инспекторе: в неё входят внешние подписи, правая подпись LabelText, естественная ширина текста и дополнительная область ColorPicker. Ширина SmallButton и RadioButtonEx определяется текстом, а не сохранённым значением W.

Включите **View → Widget footprints**, чтобы увидеть зарезервированное место. Область рядом с небольшим элементом может принадлежать его подписи или нативному контролу.

Внутри TabBar проверки перекрытия следуют активному пути вкладок. Виджеты в неактивных соседних вкладках не мешают размещению, перемещению, изменению размера, drag preview и проверке paste на тех же координатах видимой вкладки. Виджеты в той же активной вкладке по-прежнему конфликтуют; видимое содержимое отдельных перекрывающихся TabBar тоже остаётся препятствием.

- Новый виджет в занятом месте отклоняется с сообщением в статусной строке.
- При перемещении Builder может подобрать ближайшую свободную позицию на сетке.
- Недопустимое перемещение или изменение размера отклоняется либо откатывается.
- При копировании выделения ищется общее смещение, сохраняющее взаимное положение объектов.

Проверки зависят от операции и контекста вложенности и не являются нативным тестом пересечений ImGui. Рисунки могут свободно перекрываться. Тесные макеты проверяйте в Preview и в экспортированном интерфейсе.

<a name="manual-48--имена-объектов"></a>

### 4.8 · Имена объектов

При создании каждый объект автоматически получает имя с номером:

`Button_2`<br> `Slider_4`<br> `Panel_6`

Имя отображается на вкладке **Elements** и используется при генерации Lua-кода.

Например, из имени `Slider_4` формируются:

- запись позиции `pos.SLIDER_4`;
- поле состояния `state.Slider_4_val`;
- идентификатор ImGui `"##Slider_4"`.

Объекты можно переименовывать.

Используйте латинские буквы, цифры и символ `_`. Другие символы при экспорте заменяются на `_`; видимая подпись не зависит от идентификатора в коде.

По возможности используйте уникальные имена. Если после нормализации два имени совпадут, проверка перед экспортом покажет предупреждение, а экспортёр добавит суффиксы `_2`, `_3` и т. п., сохраняя уникальные ImGui ID.

<a name="manual-05-работа-с-объектами"></a>

## 05. Работа с объектами

<a name="manual-51--размещение-виджетов"></a>

### 5.1 · Размещение виджетов

Выберите виджет, затем разместите его на холсте одним из двух способов.

**Щелчок** создаёт виджет стандартного размера, заданного его контрактом.

Перемещение менее чем на **5 экранных пикселей** считается щелчком даже рядом с границей сетки.

**Перетаскивание** за этот порог позволяет сразу задать размер. По каждой оси смещение не менее **10 пикселей макета** после привязки заменяет стандартный размер. При меньшем смещении используется размер по умолчанию; фиксированные и вычисляемые размеры по-прежнему определяются контрактом виджета.

Например, Button можно сразу разместить размером 200 × 70 px. У Slider протягивание может задать ширину 300 px, но его высота останется фиксированной.

После размещения снова включается **Select**, а созданный виджет остаётся выделенным. Его параметры можно сразу изменить в инспекторе.

<a name="manual-предварительная-настройка"></a>

#### Предварительная настройка

Пока активен инструмент размещения, **Selection** показывает поддерживаемые свойства. До создания можно задать вариант, подпись, диапазон, формат, флаги, число компонентов, hint, bullet и другие доступные параметры. Применимые значения копируются в новый виджет; имя объекта присваивается автоматически.

Например, выберите Slider → Double, задайте min/max 0/100 и формат `%.1f`, затем щёлкните — виджет будет создан с этими значениями. После размещения их можно редактировать дальше.

**Reset** возвращает значения по умолчанию. Повторный щелчок по активному инструменту отменяет его.

<a name="manual-размещение-через-контекстное-меню"></a>

#### Размещение через контекстное меню

Виджет можно добавить и без панели виджетов.

Щёлкните правой кнопкой мыши по холсту. В контекстном меню отображаются все типы виджетов, сгруппированные по категориям.

Выбранный виджет будет размещён в точке щелчка.

Этот способ удобен, если вы уже знаете название нужного типа и не хотите открывать соответствующую категорию в верхней панели.

<a name="manual-52--выделение"></a>

### 5.2 · Выделение

| Действие | Результат |
| --- | --- |
| **Щелчок** | Выбрать один объект |
| **Shift + щелчок** | Добавить объекты, которые пересекают прямоугольную область между опорным и выбранным объектами |
| **Cmd/Ctrl + щелчок** | Добавить объект к выделению или исключить его |
| **Протягивание по пустому холсту** | Выделить объекты рамкой |
| **Shift + рамка** | Добавить объекты к текущему выделению |
| **Cmd/Ctrl + рамка** | Переключить состояние объектов в области рамки |
| **Щелчок по строке Elements** | Выбрать соответствующий объект на холсте |
| **Cmd/Ctrl + A** | Выбрать все объекты |
| **Esc** | Снять выделение или отменить активный инструмент |

Удержание `Shift` временно включает **Select**, когда активен инструмент рисования или размещения виджета, кроме процесса создания полигона.

Так можно изменить выделение, не отменяя текущий инструмент.

При множественном выделении появляется пунктирная рамка с маркерами, состав которых зависит от правил изменения размера выбранных объектов.

Для рисунков щелчок проверяет видимую геометрию: пустые углы, незалитая внутренняя область контура и промежуток дуги пропускают щелчок к объектам ниже. Тонкие линии имеют небольшой допуск в экранных пикселях. Видимый текст принимается во внимание, а служебная метка имени не увеличивает область попадания. Рамочное выделение по-прежнему использует габариты объекта. Полностью невидимый рисунок выбирайте через Elements.

Отдельный участник группы, выбранный через Elements, остаётся выбранным при щелчке или перетаскивании этой фигуры на холсте. Щелчок по другому, невыбранному участнику выбирает всю группу. Несколько участников, выбранных в Elements, перемещаются именно этим составом.

<a name="manual-53--перемещение-и-изменение-размера"></a>

### 5.3 · Перемещение и изменение размера

Чтобы переместить выбранный объект, перетащите его.

Чтобы изменить размер, перетащите один из маркеров выделения.

Обе операции учитывают привязку к сетке.

Количество доступных маркеров определяется контрактом виджета:

- восемь — если ширину и высоту можно изменять свободно;
- два боковых — если высота фиксирована, а ширину изменять можно;
- маркеры отсутствуют — если размер полностью определяет ImGui.

Для точного размещения используйте поля **position** и **size** в инспекторе.

Поля используют абсолютные координаты макета и следуют настройке **Snap to grid**. Отключите привязку для шага в 1 px. Значения разбираются как целые числа. Рабочая область продолжается за рамкой экспорта: рисунки можно перемещать наружу, в том числе к отрицательным координатам, используя Hand. Это не увеличивает экспортируемое окно.

Когда холст в фокусе, стрелки сдвигают выделение на один шаг сетки либо на 1 px при выключенной привязке. С `Shift` сдвиг увеличивается в десять раз. В Elements сначала нажмите Enter, чтобы передать фокус холсту.

Удерживайте **Shift при изменении размера рисунка**, чтобы сохранить пропорции. Угловой маркер оставляет противоположный угол на месте; боковой сохраняет противоположную сторону и симметрично меняет другую ось. Это работает и для выделения, состоящего только из рисунков. Виджеты сохраняют собственные контракты.

Изменение размера рисунка Text также масштабирует шрифт по меньшему коэффициенту ширины/высоты, но не ниже 6 px. Буквы не растягиваются независимо по осям. Undo восстанавливает и рамку, и размер шрифта.

<a name="manual-54--копирование-дублирование-и-удаление"></a>

### 5.4 · Копирование, дублирование и удаление

<a name="manual-copy--paste"></a>

#### Copy / Paste

`Cmd/Ctrl + C` и `Cmd/Ctrl + V`

Копирование контейнера включает всё поддерево. Вставка назначает новые ID объектов и групп редактора, сохраняет вложенность и взаимное расположение, включая концы линий и вершины полигонов. Builder начинает со смещения и при необходимости ищет общее допустимое смещение.

Копировать можно между проектами или вкладками Builder, даже после закрытия исходной вкладки. Горячие клавиши и меню используют один формат буфера; локальная копия также сохраняется для повторного открытия того же файла Builder. Доступ браузера к буферу может быть ограничен: если команда меню не сработала, используйте горячую клавишу и следуйте сообщению в статусной строке.

Существующий родитель переиспользуется только в исходном проекте. Вставка в другой проект не прикрепляет объекты к случайным контейнерам с совпавшими ID.

<a name="manual-duplicate"></a>

#### Duplicate

`Cmd/Ctrl + D`

Создаёт и сразу размещает копию — это равносильно последовательному выполнению команд Copy и Paste.

<a name="manual-alt--перетаскивание"></a>

#### Alt + перетаскивание

Начните перетаскивание с удержанием `Alt`, чтобы перемещать копию объекта, оставив оригинал на месте.

Этот способ работает и для множественного выделения.

<a name="manual-delete"></a>

#### Delete

`Del` или `Backspace`

При удалении контейнера с пользовательским содержимым Builder предлагает выбор:

| Вариант | Результат |
| --- | --- |
| Cancel | Сохранить контейнер и содержимое. |
| Keep inner widgets | Удалить контейнер, сохранив пользовательское содержимое на его позициях; внутренние обёртки вкладок и ячеек при необходимости удаляются. |
| Delete with children | Удалить контейнер вместе со всем поддеревом. |

Пустой контейнер или обычный объект удаляется сразу. Вернуть удалённое можно через **Undo**.

<a name="manual-55--история-изменений"></a>

### 5.5 · История изменений

Builder хранит **50 шагов** истории.

Последовательные изменения одного и того же свойства, выполненные в пределах **600 мс**, объединяются в один шаг. Например, несколько быстрых изменений значения `max` не создают отдельную запись истории для каждого промежуточного значения.

Команда **Undo** восстанавливает не только состояние объектов, но и выделение, которое было активно на соответствующем шаге.

При загрузке проекта история очищается. Отменить изменения, выполненные до загрузки, после этого нельзя.

<a name="manual-56--пакетное-редактирование"></a>

### 5.6 · Пакетное редактирование

Когда выделено больше одного объекта, инспектор показывает их количество и состав по типам, а из свойств — только те, которые есть у **всех** выделенных объектов. Например, для кнопки и флажка это подпись, всплывающая подсказка и маркер списка.

Если значение свойства у выделенных объектов различается, поле показывает **Mixed**. Пока вы не введёте значение, свойство не изменяется ни у одного объекта.

Поля `ΔX / ΔY` сдвигают всё выделение с учётом границ рабочей области и проверок перекрытия. Рабочая область продолжается за экспортируемой рамкой, поэтому виджет может оказаться вне экспорта. Если вместе с контейнером выделен дочерний объект, он перемещается с контейнером только один раз.

Любое пакетное изменение создаёт одну запись в истории: одна команда **Undo** возвращает исходные значения всем выделенным объектам.

<a name="manual-57--группы-редактора"></a>

### 5.7 · Группы редактора

Выберите два или больше объектов и вызовите **Edit → Group selection** (`Cmd/Ctrl + G`). Группа может включать рисунки и виджеты. Имя редактируется в Selection или командой Rename на заголовке группы в Elements. `Cmd/Ctrl + Shift + G` разгруппировывает выделение.

Группы редактора упрощают выбор и перемещение. Они сохраняются в проекте, копируются вместе с участниками и входят в Undo/Redo. Они **не** добавляют `BeginGroup` в Lua, не меняют родителей-контейнеров и не позволяют поднять рисунок выше слоя виджетов. Если в экспорте нужна группа ImGui, используйте виджет **Group** из категории Layout.

Щёлкните по заголовку группы, чтобы работать со всей группой. Строка участника в Elements выбирает только его; **Select group** возвращает к группе. Если в новое выделение входят существующие группы, Group selection объединяет их полный состав.

Щелчок правой кнопкой внутри множественного выделения, включая пустое место его рамки, открывает команды для всего выделения. **Color → Select color** применяет выбранный цвет, а **Surprise me** выбирает случайный. Конкретное свойство зависит от типа объекта; для виджетов используются подходящие слоты стиля, включая цвета вкладок.

> **Color ▸ Select color подробнее.** Для виджета команда меняет цвет кнопок, полей, заголовков и других поверхностей. Для контейнера (Group, Panel, TabBar, CollapsingHeader, TreeNode, Tab, Table, StyleRegion) она меняет цвет контейнера и его содержимого. Цвета при наведении и нажатии рассчитываются автоматически: для тёмного базового цвета они становятся светлее, для светлого — темнее. Галочка, ползунок слайдера, заливка индикатора и активная вкладка сохраняют цвет темы, если он достаточно контрастен; иначе используется насыщенный оттенок выбранного цвета. В Editor выбранным цветом показывается только рамка. Preview показывает итоговый вид, включая содержимое контейнера. Для ColorEdit, ColorPicker, ColorButton и TextColored команда также задаёт значение цвета, а для TreeNode — цвет заголовка.

| `TreeNode` | Раскрываемый узел с отступом для вложенных элементов. — *Применяется для иерархий: папки, треки, вложенные настройки.* |
| `TabBar` | Полоса вкладок с переключением страниц содержимого. — *Применяется для разделения панели на страницы вида Main / FX / MIDI.* |
| `Table` | Сетка строк и столбцов, содержащая другие виджеты. — *Применяется для выровненных макетов, матриц и построчных данных.* |

<a name="manual-примечания-к-каталогу"></a>

### Примечания к каталогу

**Slider, Drag и Input.** Slider имеет трек и границы; Drag меняет значение горизонтальным перетаскиванием; Input поддерживает прямой числовой ввод. Набор полей отличается: Slider предлагает границы и флаги, Drag добавляет скорость, а скалярный Input — параметры шага. SliderAngle и семейства с суффиксом N имеют собственные наборы полей; см. приложение B.

**Семейства с суффиксом N** (SliderN, DragN, InputN). В экспорте создаётся `reaper.new_array` на количество элементов, заданное в поле **array size**, и управление выполняется одним вызовом. Обычные семейства вместо этого используют поле **value components** со значением от 1 до 4: генерируются вызовы вида `SliderDouble2` или `DragInt3` с отдельными скалярными переменными.

**HelpMarker.** В экспорте выводится как неактивный символ `(?)`. Текст подсказки берётся из поля **tooltip**, а не из подписи.

**Combo и ListBox.** В экспорт добавляются пять элементов-заглушек: `item_0…item_4` и `Item 1…Item 5`. Списки элементов в этой сборке не редактируются, задайте их в готовом коде.

**TextColored.** Начальный цвет по умолчанию — чёрный. Preview и Lua используют выбранный цвет текста; Editor сохраняет нейтральное оформление выделения и диагностики, не используя цвет текста как цвет рамки.

**RadioButtonEx.** Кнопки с одинаковым значением в поле **group** используют общую переменную состояния, каждой кнопке задаётся собственное значение в поле **radio value**. Так в экспорте реализуется взаимное исключение.

<a name="manual-07-контейнеры"></a>

## 07. Контейнеры

Общие свойства контейнеров описаны в [§4.6](#manual-46--контейнеры-и-вложенность): геометрическая вложенность, рабочие области разных типов и поведение при изменении размера. Ниже описаны различия между контейнерами.

<a name="manual-71--panel"></a>

### 7.1 · Panel

Panel — это дочернее окно ImGui: область с рамкой, при необходимости прокручиваемая. Применяется для боковых панелей, блоков настроек и групп виджетов с видимой границей.

- **border.** Отображает рамку. Включён по умолчанию. При выключенном параметре рамка исчезает, но Panel по-прежнему обрезает и прокручивает содержимое.
- **h-scroll.** Добавляет горизонтальную полосу прокрутки. Без неё содержимое шире панели обрезается.

```lua
reaper.ImGui_BeginChild(ctx, "##Panel_6", 220, 140, reaper.ImGui_ChildFlags_Borders(), 0)
  -- дочерние виджеты, для каждого задаётся SetCursorScreenPos
reaper.ImGui_EndChild(ctx)
```

Если для Panel задан пользовательский цвет, Builder использует его как фон дочернего окна; иначе применяется цвет активной темы, если выбрана тема, отличная от Default. Переопределение включается перед `BeginChild` и снимается сразу после вызова: фон панели уже создан, а вложенные панели могут применить собственный цвет.

<a name="manual-72--group"></a>

### 7.2 · Group

Group не имеет рамки и фона. В экспорте выводятся `BeginGroup` и `EndGroup`, поэтому ImGui обрабатывает вложенные виджеты как один блок. Если у Group есть непустая подпись, Builder отдельно рисует её над группой; само содержимое не сдвигается.

Используйте Group, когда несколько виджетов должны перемещаться вместе в Builder и составлять один логический блок в экспортируемом коде. Если границу блока нужно видеть, используйте Panel.

В режиме Preview Group отображается штриховкой.

<a name="manual-73--styleregion"></a>

### 7.3 · StyleRegion

StyleRegion применяет стилевые переопределения к вложенным виджетам, не затрагивая остальной макет. Используйте его, чтобы назначить группе виджетов общие цвета, скругление, выравнивание или шрифт. Быстро изменить цвет выделенных объектов можно через контекстное меню **Color ▸**; для контейнера команда также перекрашивает его содержимое (см. §5.7).

> Иллюстрация. Инспектор StyleRegion. У каждого переопределения есть флажок. Снятый флажок означает, что параметр не изменяется, поэтому область может переопределить только цвет кнопок и унаследовать остальные параметры.

<p align="center"><img src="screenshots/7_3___StyleRegion.png" alt="Инспектор StyleRegion с переопределениями цвета, скругления, выравнивания и шрифта" width="380"></p>

| Переопределение | Экспорт |
| --- | --- |
| text color | `PushStyleColor(Col_Text)` |
| frame bg | `PushStyleColor(Col_FrameBg)` |
| button color | `PushStyleColor(Col_Button)` |
| rounding | `PushStyleVar(StyleVar_FrameRounding)` |
| selectable align | `PushStyleVar(StyleVar_SelectableTextAlign, x, y)`, оба значения от 0 до 1 |
| font | `CreateFont(family, flags)` при запуске, затем `PushFont(ctx, font, size)` вокруг дочерних виджетов |

**font** предлагает пять общих семейств — sans-serif, serif, monospace, cursive и fantasy, — независимые переключатели Bold и Italic и размер от 6 до 72 px. Builder создаёт каждое уникальное сочетание семейства и начертания одним вызовом `CreateFont` и прикрепляет шрифт к контексту до первого кадра. `PushFont` выполняется после стилевых переопределений, а соответствующий `PopFont` — перед их снятием, поэтому шрифт применяется только к виджетам внутри StyleRegion.

> **Примечание.** В Preview StyleRegion применяет к дочерним элементам поддерживаемые цвета, скругление и шрифт. Переопределение цвета текста распространяется на внешние подписи, а также на Text, Separator, SeparatorText, LabelText и BulletText, которые рисуются через draw list. Builder определяет их итоговые цвета при генерации Lua. Маркер `Aa` в служебном заголовке показывает, что включено переопределение шрифта.

<a name="manual-74--collapsingheader-и-treenode"></a>

### 7.4 · CollapsingHeader и TreeNode

Оба контейнера могут сворачивать содержимое во время работы интерфейса. CollapsingHeader — полоса во всю ширину, TreeNode — узел с отступом и стрелкой. Оба экспортируются с `TreeNodeFlags_DefaultOpen` и при запуске раскрыты.

У TreeNode есть параметр **hdr color**. Значение **default** выбирает чёрный или белый текст для контраста с холстом, **custom** использует выбранный цвет. Экспортёр применяет этот цвет к подписи в обоих режимах.

В Builder оба контейнера всегда отображаются раскрытыми.

**bullet instead of arrow** заменяет стрелку раскрытия на маркер через `TreeNodeFlags_Bullet`. Узел всё равно можно раскрывать и сворачивать: он не становится листом. Это нативный флаг дерева/заголовка, не связанный с декоративным **prefix bullet** у некоторых обычных виджетов.

<a name="manual-75--tabbar"></a>

### 7.5 · TabBar

> Выберите служебный заголовок контейнера **Tabs**, чтобы открыть список **tabs**. Имена редактируются в строках, × удаляет страницу вместе с содержимым, кнопка добавления создаёт новую. Последнюю вкладку удалить нельзя.

При размещении TabBar создаётся с двумя вкладками. Щелчок по вкладке на холсте переключает активную страницу; только её содержимое отображается, обрабатывается и учитывается проверками перекрытия. Виджеты, размещённые на странице, принадлежат соответствующему элементу TabItem.

В экспорте вызовы `BeginTabItem` и `EndTabItem` вкладываются в `BeginTabBar` и `EndTabBar`, а виджеты каждой страницы — внутрь своего элемента.

Полоса вкладок заключена в прозрачную дочернюю область заданной ширины и высоты, с нулевыми отступами и без прокрутки. Благодаря этому нативное подчёркивание вкладки ограничено областью Tabs, а не тянется до правого края родительского окна. Содержимое обрезается по этой области. Цвета выбранной, обычной и наведённой вкладки следуют активной теме; пользовательский цвет Tabs также попадает в экспорт.

<a name="manual-76--table"></a>

### 7.6 · Table

> Иллюстрация. Инспектор Table. Счётчики строк и столбцов, подпись и режим ширины для каждого столбца, флажок строки заголовков, четыре флага таблицы и общая политика размеров.

<p align="center"><img src="screenshots/7_6___Table.png" alt="Инспектор Table с настройками столбцов и строк" width="380"></p>

Table — это сетка ячеек-контейнеров. Число строк и столбцов — от 1 до 16; новая таблица содержит 3 × 3 ячейки. Если уменьшение сетки удаляет заполненные ячейки, диалог предлагает **OK** для удаления их содержимого или **Cancel**, чтобы сохранить виджеты на верхнем уровне. Cancel сохраняет содержимое, а не отменяет изменение размера таблицы.

| Параметр | Описание |
| --- | --- |
| columns / rows | От 1 до 16 по каждой оси. Увеличение создаёт ячейки, уменьшение удаляет их и спрашивает, что делать с содержимым. |
| Ширина столбца | Имеет три значения. При значении **Auto** флаг не задаётся. При значении **Fix** задаётся `WidthFixed` и ширина в пикселях. При значении **Str** задаётся `WidthStretch` и весовой коэффициент. |
| Высота строки | Запрашивает минимальную высоту в пикселях. Строки без значения делят оставшееся место; слишком большие запросы уменьшаются до области таблицы, а если заданы все строки, последняя получает остаток. Разрешённая высота передаётся как минимум в `TableNextRow`. |
| header row | Добавляет вызов `TableHeadersRow` и резервирует на холсте полосу подписей высотой 18 px. |
| Borders | Границы ячеек. |
| RowBg | Чередующийся фон строк. |
| Resizable | Разрешает изменять ширину столбцов во время работы плагина. |
| ScrollY | Включает вертикальную прокрутку. Только при включённом ScrollY высота таблицы передаётся в ImGui. |
| sizing | Политика размеров для столбцов со значением **Auto**: `SizingFixedFit` или `SizingStretchSame`. |

Если включён **header row**, Builder вычитает из высоты таблицы полосу заголовков столбцов 18 px, затем рассчитывает итоговую высоту строк. Служебная вкладка Table находится вне рамки и в этот расчёт не входит. Ячейки выводятся по строкам. Дочерние элементы сохраняют локальное положение в ячейке; экспортёр пересчитывает координаты от фактической точки отсчёта ячейки и получает текущий draw list. Подписи и другая draw-list геометрия используют обрезку и прокрутку таблицы. Это сохраняет заданные смещения при нативной прокрутке и изменении ширины столбцов; автоматической потоковой раскладки здесь нет.

> **Обратите внимание.** При помещении в ячейку Builder старается сохранить точку отпускания, ограничивает положение внутренней областью с отступом 4 px и при необходимости уменьшает выходящие за границу размеры. Центрирования нет. Если центр виджета не попал в ячейку, но рамка пересекает таблицу, объект переносится за ближайший край таблицы.

<a name="manual-08-справочник-инспектора"></a>

## 08. Справочник инспектора

> Инспектор показывает тип виджета, вариант, имя, подпись, свойства по контракту, позицию, размер и кнопку удаления.

<p align="center"><img src="screenshots/08__Inspector_reference.png" alt="Инспектор виджета Input, вариант Double, до размещения" width="380"></p>

**Идентификация**

| Поле | Описание |
| --- | --- |
| variant | Выбранный тип семейства: Int / Double или RGB / RGBA. Его можно выбрать до размещения; у существующего виджета поле доступно только для чтения. |
| name | Идентификатор объекта. Определяет имена переменных в коде и идентификатор ImGui. Должен быть уникальным, допустимы символы `[A-Za-z0-9_]`. |
| parent | Цепочка контейнеров, в которых находится виджет. Только для чтения. |
| label / text | Видимый текст. Для виджетов семейства Text — само содержимое, для виджетов — подпись над виджетом или внутри него. |
| hint | Только InputTextWithHint. В инспекторе поле называется **placeholder**; текст выводится, пока поле пустое. |
| value | Только LabelText. Значение слева, доступное только для чтения; подпись находится справа. |
| url | Только TextLinkOpenURL. Адрес, открываемый экспортированной ссылкой. Пустое значение экспортирует `https://example.com`. |

**Числовые параметры**

| Поле | Описание |
| --- | --- |
| value components | Значение от 1 до 4. Генерируется многокомпонентный вызов, например `SliderDouble3`, с отдельным полем состояния для каждого компонента. |
| array size | Только семейства с суффиксом N. Размер массива `reaper.new_array`, от 2 до 64. |
| min / max | Границы диапазона. Если поля пустые, применяются значения по умолчанию для типа. |
| speed | Только семейства Drag. Изменение значения на один пиксель перемещения мыши. |
| step / step fast | Скалярные InputInt/InputDouble. Явные шаги управления. Для InputInt с 2–4 компонентами эти аргументы в экспорт не передаются. |
| format | Формат в стиле printf, например `%.2f` или `%d dB`. Определяет и отображение значения в виджете. |
| format min / max | Только DragRange. Отдельные форматы для нижней и верхней границы, например `Min: %d` и `Max: %d`. |
| numeric flags | Clamp, Log, NoInput, Wrap. См. [§9](#manual-09-флаги). |

Пустые числовые поля используют значения по умолчанию; очистка удаляет явное переопределение. Диапазон Slider/Drag для Int по умолчанию 0–100, для Double — 0–1. Скорость Drag по умолчанию равна **1**, в том числе при собственном формате. Для иных диапазонов, шага, скорости или формата задайте значения явно.

**Внешний вид и поведение**

| Поле | Описание |
| --- | --- |
| tooltip | В инспекторе поле называется **hint**. Добавляет `SetItemTooltip` для поддерживаемых виджетов. Text, Separator, SeparatorText, LabelText, BulletText, TextWrapped, StyleRegion, Table и TableCell его не предлагают. У Panel, Group, CollapsingHeader, TreeNode, TabBar и TabItem подсказка экспортируется для нативного элемента контейнера. |
| bullet | **prefix bullet** рисует декоративную точку слева от поддерживаемых обычных виджетов. **bullet instead of arrow** у TreeNode и CollapsingHeader включает нативный флаг дерева. См. памятку ниже. |
| color | Начальный цвет TextColored, ColorEdit3/4, ColorPicker3/4 и ColorButton. Доступен для одного объекта и подходящего пакетного выделения. |
| alpha | Значение 0–255 для вариантов RGBA, ColorButton и TextColored. Для ColorEdit4/ColorPicker4 альфа применяется только вместе с явно заданным цветом. |
| text tone | Только TextWrapped: Auto, Dark или Light. Auto следует разрешённому цвету текста темы/стиля, явный тон помогает управлять контрастом. |
| direction | Только ArrowButton. Направление стрелки: Left, Right, Up, Down. |
| overlay | Только ProgressBar. Текст поверх полосы. Пустое поле экспортирует пустую строку, поэтому автоматический процент не запрашивается. |
| indeterminate | Только ProgressBar. Анимация вместо отображения значения. |
| group / radio value | Только RadioButtonEx. Общая переменная состояния и значение этой кнопки. |
| hdr color | Только TreeNode. Цвет подписи узла: default или собственный. |
| border / h-scroll | Только Panel. Рамка и горизонтальная прокрутка. |
| EEL2 callback | Только текстовые поля ввода. См. ниже. |

**Памятка по bullet**

Prefix bullet — оформление Builder, а не универсальная опция ReaImGui. У поддерживаемых обычных виджетов точка рисуется в Editor, Preview и Lua на **8 px левее** начала элемента. Цвет разрешается из темы/StyleRegion; позиция самого элемента и его подписи не меняется. Оставляйте место слева: граница родительского контейнера может обрезать точку.

| Сценарий | Управление |
| --- | --- |
| Точка перед поддерживаемым обычным элементом | **prefix bullet**; точный список типов — в приложении B. |
| Маркер вместо стрелки раскрытия | **bullet instead of arrow** у TreeNode/CollapsingHeader; раскрытие продолжает работать. |
| Обычная строка маркированного текста | Виджет **BulletText**. |
| Panel, Group, StyleRegion, TabBar, TabItem, Table, TableCell | Управления bullet нет; старые сохранённые значения игнорируются. |

ColorButton, Selectable, TextWrapped, Text, Separator, SeparatorText, LabelText и BulletText не имеют дополнительного prefix bullet. BulletText уже рисует собственный маркер.

**Геометрия**

Поля **position** (X, Y) и **size** (W, H) используют целые пиксели макета и учитывают Snap to grid. Фиксированные размеры доступны только для чтения. Значение H у ColorPicker вычисляется по ширине элемента без бокового предпросмотра и выбранным флагам.

Для рисунков дополнительно выводится строка **primitive order** с кнопками back, backward, forward и front. Порядок изменяется только внутри слоя рисунков: рисунки не отображаются поверх виджетов.

**Колбэки EEL2**

> Иллюстрация. Инспектор текстового поля. Сверху — базовые флаги, ниже — события колбэков, затем поле с кодом EEL2.

Выберите размещённое текстовое поле и введите код в **EEL2 callback**. Если событие не выбрано, первый непустой ввод автоматически включает **OnEdit**. Выберите нужные события во флагах; OnTab и OnUp/Down доступны только однострочным полям. Скрипт компилирует и прикрепляет колбэк при запуске. Подсказка предупреждает, если у кода нет события. Флаги колбэка без непустого кода считаются ошибкой проверки перед экспортом: добавьте код или отключите события.

<a name="manual-09-флаги"></a>

## 09. Флаги

## 10. Примитивы рисования

> Иллюстрация. Примитивы на холсте. Прямоугольник, круг, треугольник, линия, текст и дуга. Все примитивы экспортируются вызовами draw list и располагаются под слоем виджетов.

<p align="center"><img src="screenshots/Canvas_with_primitives.png" alt="Все примитивы рисования на холсте" width="500"></p>

Чтобы нарисовать фигуру, выберите инструмент в палитре и протяните указатель по холсту. Полигон строится иначе: задавайте вершины щелчками. Замкните фигуру повторным щелчком по первой точке, двойным щелчком или клавишей `Enter`. Клавиша `Esc` отменяет незавершённый полигон.

| Примитив | Параметры | Экспорт |
| --- | --- | --- |
| Прямоугольник | fill, stroke, rounding, thickness, opacity | `AddRectFilled` и `AddRect` |
| Круг | fill, stroke, thickness, opacity | `AddCircle(Filled)`; при W ≠ H — `AddEllipse(Filled)` |
| Треугольник | fill, stroke, thickness, orient (четыре направления) | `AddTriangle(Filled)` |
| Линия | stroke, thickness | `AddLine` |
| Полигон | fill, stroke, thickness, список точек | `PathFillConvex` для выпуклых фигур; триангуляция через `AddTriangleFilled` для невыпуклых |
| Дуга | `ring`: stroke, thickness, начальный и конечный угол; `pie`: те же свойства плюс fill | `PathArcTo` и `PathStroke`; в режиме `pie` также `PathFillConvex` |
| Текст | текст, цвет, размер, выравнивание по горизонтали и вертикали | `AddTextEx` с явным размером шрифта; измерение текста для выравнивания |

> Иллюстрация. Инспектор дуги. Углы задаются в градусах по правилам ImGui: 0° соответствует направлению вправо, значения растут по часовой стрелке. Развёртка 270° с началом в 135° соответствует стандартной шкале поворотной ручки.

<p align="center"><img src="screenshots/Arc.png" alt="Инспектор Arc с режимом ring, углами и порядком примитива" width="380"></p>

Рисунки при экспорте обрезаются по макету и попадают в код, если хотя бы пересекают его: прямоугольник, частично выходящий за край, будет выведен, а выходящую часть обрежет ImGui. Для виджетов правило строже — виджет должен целиком находиться внутри фрейма, иначе он не экспортируется.

**Размер и цвет текста рисунка.** Значение **text size** экспортируется явно. Изменение рамки масштабирует шрифт по правилам §5.3. Новый Text автоматически использует итоговый цвет текста проекта; выбор цвета в палитре фиксирует пользовательский цвет. Холст и Lua используют одно и то же значение. Текст не сжимается до произвольной ширины.

**Связанные углы дуги.** Включите **Link angles**, чтобы сохранять развёртку: изменение Start на величину сдвигает End на ту же величину, и наоборот. Дуга обновляется во время ввода. Настройка сохраняется и работает при пакетном редактировании дуг. Она связывает углы, а не цвета заливки и обводки.

<a name="manual-заливка-и-обводка"></a>

### Заливка и обводка

У каждой доступной строки fill/stroke есть собственный флажок **disable**. Он отключает компонент, не стирая выбранный цвет. Элементы независимы: фигура может иметь заливку, обводку, оба компонента или ни одного.

Stroke можно отключить также у Line и дуги в режиме ring. Полностью отключённый или прозрачный рисунок остаётся в проекте; выбирайте его через Elements. Цвета fill и stroke редактируются независимо; в версии 1.0.70 связать их нельзя.

Если оставить поле opacity пустым, прежнее значение восстановится, когда поле потеряет фокус. То же правило действует при пакетном редактировании.

ImGui напрямую заливает только выпуклые пути. Невыпуклый полигон Builder триангулирует и экспортирует несколькими вызовами `AddTriangleFilled`; контур остаётся одним замкнутым путём.

<a name="manual-11-настройки-холста-и-проекта"></a>

## 11. Настройки холста и проекта

<a name="manual-заголовок-окна"></a>

### Заголовок окна

Название, под которым макет откроется в REAPER, показано в синей шапке над холстом. Щёлкните по нему — строка станет полем ввода. `Enter` применяет название, `Esc` отменяет правку.

Заголовок попадает в сгенерированный скрипт (`CreateContext` и `ImGui_Begin`), сохраняется в файле проекта и задаёт имя скачиваемого файла: *Track Tools* → `Track_Tools.lua`. Апостроф в названии экранируется, поэтому скрипт остаётся работоспособным.

<a name="manual-размер"></a>

### Размер

Поля W и H на вкладке Canvas задают размер содержимого окна плагина. Эти значения передаются в экспорт как `W, H`. Чтобы применить их, нажмите `Enter` или уберите фокус с поля. Тот же результат даёт перетаскивание маркера ⇲.

<a name="manual-фон"></a>

### Фон

- **Default.** Холст отображается в цветах активной темы, а в экспорте сохраняется собственный фон окна ImGui. Если выбрана тема, отличная от Default, Builder дополнительно применяет её цвет фона к дочернему окну холста через `PushStyleColor`.
- **Custom.** Выберите цвет и opacity во встроенной палитре вкладки Canvas. Opacity смешивает цвет с белым; экспорт записывает получившийся непрозрачный цвет как `Col_WindowBg`. Прозрачным окно REAPER от этого не становится.

<a name="manual-выбор-цвета"></a>

### Выбор цвета

Образцы цветов рисунков, поддерживаемых виджетов, StyleRegion, пакетного редактирования и редактора темы открывают всплывающую палитру Builder. Обычно она появляется справа и сверху, а у края окна смещается влево или вниз. На вкладке Canvas используется отдельная встроенная палитра фона.

Во всплывающем окне есть поле насыщенности/яркости, полоса оттенка, поле **HEX** и недавние образцы. Экранная пипетка отображается только в браузерах, которые её поддерживают. При открытии фокус получает HEX; допустимы `#RRGGBB` и `#RGB`. Изменения применяются сразу. `Enter` закрывает окно, `Esc` закрывает его и возвращает фокус, но не отменяет уже применённый цвет. Изменения цвета объединяются в истории Undo по тем же правилам, что и изменения других полей.

Недавние образцы общие для всех цветовых полей и сохраняются до перезагрузки страницы.

<a name="manual-сетка"></a>

### Сетка

Флажок **Show grid** включает отображение тонкой сетки; настройка сохраняется отдельно для режимов Editor и Preview. Параметр **Step** задаёт шаг сетки — 2, 5 или 10 px. Этот же шаг используется для привязки.

<a name="manual-audit-grid"></a>

### Audit grid

Команда *View → Reference grid in export* включает пурпурную измерительную сетку с шагом 50 px. В отличие от обычной сетки, audit grid попадает в экспорт: в генерируемый код добавляется блок, который рисует ту же сетку в окне REAPER. Так можно проверить соответствие координат в Builder и в окне REAPER. Перед выпуском скрипта отключите эту команду.

<a name="manual-масштаб-и-панорамирование"></a>

### Масштаб и панорамирование

Масштаб изменяется от **50% до 250%**. Готовые значения доступны в статусной строке, `Cmd/Ctrl` + колесо мыши масштабирует относительно курсора, а кнопка ⤢ вписывает макет. Инструмент Zoom увеличивает щелчком и уменьшает через `Alt/Option + щелчок`. Для панорамирования выберите Hand или удерживайте Space до начала перетаскивания. Рабочая область расширяется для рисунков, вынесенных за пределы макета. Масштаб и панорамирование меняют только вид, а не координаты объектов.

<a name="manual-13-режим-preview"></a>

## 13. Режим Preview

> Иллюстрация. Режим Preview. Метки имён, заголовки контейнеров и элементы выделения не выводятся. Виджеты отображаются приближённо к своему виду в ImGui с учётом активной темы.

Переключатель Editor / Preview над холстом меняет режим отображения. В Preview нельзя перетаскивать, менять размер или размещать объекты прямо на холсте, но проект не блокируется: инспектор и команды редактирования продолжают работать. Щелчок выбирает виджет, а не запускает экспортированное управление. Переключайте вкладки в режиме Editor.

Штрихованными заглушками отображаются **Group**, **Table** и **ColorPicker3/4**. **TextWrapped** показывает перенос текста, включая длинные строки без пробелов, с учётом параметра **text tone**, стиля и шрифта. При наличии схематичных объектов внизу появляется баннер.

**Ограничения Preview:**

- ColorEdit и другие нативные элементы могут показывать не все флаги и взаимодействия. Preview приблизительно воспроизводит макет, но не запускает ReaImGui и не выполняет Lua.
- Переопределение цвета текста в StyleRegion применяется к внешним подписям и в Preview, и в экспорте; остальные свойства могут отображаться схематично.
- ProgressBar показывает фиксированное заполнение около 45% и не воспроизводит экспортируемую анимацию. Числовые элементы также показывают условные значения.
- Текст **overlay** виден на холсте и в Editor, и в Preview.

<a name="manual-14-экспорт"></a>

## 14. Экспорт

<a name="manual-проверка-перед-экспортом"></a>

### Проверка перед экспортом

В верхней части окна *Export* расположена панель проверки. Она запускается при каждом открытии окна и делит найденное на три уровня.

- **Ошибка.** Проверка нашла условие, блокирующее экспорт: недопустимые ID, связи родителей, геометрия, типы виджетов, поддерживаемые числовые поля или события колбэка без кода. *copy* и *download* остаются недоступны до исправления. Проверяется структура проекта, но Lua не исполняется и не все нативные аргументы валидируются; оставшиеся ограничения форматов и диапазонов указаны в §17.
- **Предупреждение.** Экспорт доступен, но настройка или пропуск требуют внимания: объекты вне макета, дочерние элементы исключённого контейнера, обрезанные рисунки, совпадающие имена, повторяющиеся значения radio, пустой TabBar или отсутствующие ячейки Table.
- **Информация.** Одна строка со счётчиком: сколько элементов не имеют видимой подписи.

В заголовке панели указано, сколько объектов **не попадёт** в экспорт и сколько будет экспортировано из общего числа. Просмотрите эту сводку: по одному только сгенерированному коду исключённые объекты определить нельзя.

Щелчок по строке проверки выделяет соответствующий объект на холсте.

> Вкладка ReaImGui окна Export содержит сгенерированный скрипт: создание контекста, таблицы позиций и состояния, функцию отрисовки и цикл defer. Кнопка **copy** копирует код в буфер обмена.

<a name="manual-структура-генерируемого-файла"></a>

### Структура генерируемого файла

Код всегда имеет одинаковую структуру:

1. **Заголовочные комментарии.** Размер холста и правила размещения.
2. **Контекст и размеры.** Вызов `CreateContext`, значения `W, H` и `OUTER_H`. Последнее добавляет высоту полосы заголовка, чтобы область содержимого совпадала с размерами макета.
3. **Таблица позиций.** Координаты X/Y и ширина виджетов перечислены в `local pos = { … }` в начале файла. Многие координаты и размеры также встроены прямо в вызовы виджетов и draw list. Для согласованного изменения правьте проект Builder и экспортируйте заново.
4. **Таблица состояния.** `local state = { radioGroups = {} }` содержит интерактивные значения, отдельное пространство общих radio-групп и массивы `reaper.new_array` для семейств N. Таблицы не создают отдельную локальную переменную верхнего уровня для каждого виджета.
5. **Шрифты и колбэки EEL2.** Создаются и прикрепляются один раз, до цикла, если их использует хотя бы одна StyleRegion или поле ввода.
6. **Функция `draw()`.** Задаёт стиль макета, открывает окно и дочерний холст, получает draw list и точку отсчёта текущей области, применяет тему, рисует примитивы и выводит виджеты в порядке дерева. Вложенные дочерние окна и ячейки Table при необходимости создают собственный контекст рисования.
7. **Цикл `defer`.**

<a name="manual-правила-размещения-в-коде"></a>

### Правила размещения в коде

Обычный виджет использует запись таблицы позиций:

```lua
reaper.ImGui_SetCursorScreenPos(ctx,
  ox + pos.SLIDER_2.x, oy + pos.SLIDER_2.y)
reaper.ImGui_SetNextItemWidth(ctx, pos.SLIDER_2.w)
```

Точка отсчёта и draw list должны принадлежать активной области рисования. Корневой холст получает их после открытия дочернего окна; вложенные области и ячейки таблицы используют текущий исполняемый контекст. Так корпуса виджетов, внешние подписи и draw-list геометрия остаются выровненными с учётом обрезки и прокрутки.

Координаты и размеры встречаются также прямо в вызовах. Изменение одной записи `pos` не является полной правкой макета; по возможности обновите проект и экспортируйте снова.

Нулевые padding и spacing заданы намеренно. Добавляя в Lua потоковые виджеты, настройте подходящие отступы или продолжайте явно задавать позицию.

<a name="manual-состав-экспорта"></a>

### Состав экспорта

- Виджет экспортируется, только если целиком находится внутри границ макета. Проверка выполняется по полной занятой области виджета. Виджет, выходящий за край, в код не попадает.
- Рисунок экспортируется, если пересекает границы макета.
- Audit grid экспортируется, если включена.

<a name="manual-15-сохранение-и-загрузка"></a>

## 15. Сохранение и загрузка

**JSON-проект** сохраняет редактируемый макет. Lua — выходной формат, его нельзя импортировать обратно в Builder.

| Команда | Поведение |
| --- | --- |
| **Save Project** · `Cmd/Ctrl + S` | Сохраняет в выбранный файл проекта. При первой записи браузер с прямым доступом к файлам предлагает выбрать расположение. |
| **Save As…** · `Cmd/Ctrl + Shift + S` | Выбирает новое имя или расположение проекта. |
| **Load Project** | Открывает JSON-проект. При поддержке прямого доступа последующие Save в текущем сеансе записывают в этот файл. |
| **New Project** | Создаёт пустой макет 550 × 400, сохраняя текущие заголовок, фон, тему, сетку и привязку. |
| **Restore projects…** | Открывает список черновиков закрытых сеансов, которые можно восстановить. |

Прямая запись зависит от поддержки и разрешений браузера. После выбора файла повторный Save использует его в текущем сеансе, хотя браузер может снова запросить разрешение. Вид и текст системных запросов определяет браузер.

Если прямой доступ недоступен, Builder скачивает JSON-копию. В таком режиме он не может перезаписать исходный файл или подтвердить завершение загрузки. Сообщение в статусной строке различает прямое сохранение и скачанную копию.

Отмена Save As или ошибка записи сохраняют открытый проект и данные восстановления. Правки, внесённые во время записи и не попавшие в снимок, остаются несохранёнными.

Перед заменой изменённого проекта через New, Load или Restore Builder предлагает **Save / Discard / Cancel**. Отменённая или неудачная загрузка не заменяет текущий макет. Входные данные проверяются заранее; некорректные ID, ссылки и другие повреждения отклоняются. Старые проекты при успешной загрузке нормализуются под актуальную структуру. История Undo очищается.

Файл проекта включает объекты и их вложенность, группы редактора и имена, порядок слоёв, связанные углы дуг, свойства виджетов, заголовок, размеры, фон, активную тему с пользовательским определением, audit grid, привязку и шаг сетки. Масштаб, история Undo, режим Editor/Preview, видимость обычной сетки и панелей не являются переносимыми настройками проекта.

<a name="manual-автосохранение-и-восстановление"></a>

### Автосохранение и восстановление

Builder хранит черновики восстановления в локальном хранилище браузера. Команда **File → Restore projects…** показывает и восстанавливает черновики закрытых сеансов. Проекты, всё ещё открытые в активной вкладке, в список не попадают.

Успешная прямая запись удаляет завершённый черновик. Если во время записи появились новые правки, их черновик остаётся. При скачивании файла данные восстановления сохраняются, поскольку браузер не сообщает Builder, завершилась или была отменена загрузка. После восстановления черновика сохраните его как файл проекта.

При выходе с несохранёнными изменениями браузер может показать стандартное подтверждение закрытия страницы. Его наличие и текст зависят от браузера и не связаны с диалогом Builder Save/Discard/Cancel.

Хранилище восстановления и пользовательских тем связано с браузером и может исчезнуть при очистке данных сайта; поведение для локальных файлов также различается. Надёжной переносимой копией остаётся JSON-проект.

<a name="manual-17-ограничения-сборки"></a>

## 17. Ограничения версии

Ниже перечислены ограничения версии **1.0.70**.

- **Редактирование элементов Combo и ListBox.** Экспорт содержит пять элементов-заглушек. Замените их строки в Lua; состояние выбора и вызовы виджета уже сгенерированы.
- **Произвольный поворот рисунков.** Для Arc доступны углы, а для Triangle — параметр orient; общего маркера или свойства поворота нет.
- **Импорт и экспорт отдельного файла темы.** Активная тема сохраняется в JSON-проекте.
- Preview не исполняет ReaImGui. Group, Table и ColorPicker остаются схематичными; нативные шрифты, взаимодействия и часть флагов проверяйте в REAPER.
- Виджеты вне рамки экспорта исключаются. Вместе с контейнером исключается содержимое. Пересекающие рамку рисунки экспортируются с обрезкой; проверяйте результаты preflight.
- W/H корпуса не всегда описывают полную занимаемую область. Внешним подписям, тексту естественной ширины и ColorPicker требуется дополнительное место; **prefix bullet** может обрезаться левой границей родителя.
- StyleRegion, Table и TableCell не поддерживают **hint**, поскольку не создают одного нативного элемента, к которому можно привязать подсказку. Для справочного текста используйте поддерживаемый виджет или HelpMarker.
- SliderN может показывать Wrap среди числовых флагов, но экспортёр удаляет Wrap из вызова Slider; используйте его с Drag.
- Для ColorEdit4/ColorPicker4 явно задайте и color, и alpha, если требуется конкретная начальная прозрачность.
- Форматы чисел и экстремальные границы Double-slider проверяются не полностью. Используйте один совместимый спецификатор (например `%d` для Int или `%.2f` для Double) и разумный диапазон. Чистый preflight не доказывает корректность любого формата или предельного значения в ReaImGui.
- Рисунки остаются ниже виджетов. Порядок внутри слоя не отменяет обрезку нативными дочерними окнами и не создаёт глобальный слой поверх интерфейса.
- Разрешения браузера на файлы и буфер обмена влияют на сохранение и копирование. Черновики и пользовательские темы в браузере не заменяют переносимый проект.
- Имя Lua-файла выводится из заголовка окна; неподдерживаемые символы заменяются подчёркиванием, запасное имя — `MyPlugin.lua`.

## Приложение C · Как читать сгенерированный файл

Эти фрагменты взяты из экспорта версии 1.0.70 для макета **600 × 400** с Button_1 («Play») в точке (40, 60) и Slider_2 («Gain») в точке (40, 130). Они показывают структуру позиций и состояния, но не являются полным исполняемым скриптом. Полный файл создаётся через Export.

```lua
-- Positions
local pos = {
  BUTTON_1 = { x=40, y=60, w=100 },
  SLIDER_2 = { x=40, y=130, w=120 },
}

local state = { radioGroups = {} }
-- Widget state
state.Slider_2_val = 0.0
```

Функция отрисовки открывает дочерний холст до получения его draw list и точки отсчёта. После этого виджеты используют эти значения:

```lua
    -- Button_1 [Button]
    reaper.ImGui_SetCursorScreenPos(ctx, ox + pos.BUTTON_1.x, oy + pos.BUTTON_1.y)
    if reaper.ImGui_Button(ctx, "Play##Button_1", 100, 20) then
      -- TODO: Button_1 pressed
    end

    -- Slider_2 [SliderDouble]
    reaper.ImGui_SetCursorScreenPos(ctx, ox + pos.SLIDER_2.x, oy + pos.SLIDER_2.y)
    reaper.ImGui_SetNextItemWidth(ctx, pos.SLIDER_2.w)
    do
      local _label = "Gain"
      if _label ~= "" then
        local _tw, _th = reaper.ImGui_CalcTextSize(ctx, _label)
        reaper.ImGui_DrawList_AddText(dl, ox+40, oy+128-_th, 0x000000FF, _label)
      end
      local _rv
      _rv, state.Slider_2_val = reaper.ImGui_SliderDouble(ctx, "##Slider_2", state.Slider_2_val, 0.0, 1.0)
    end
```

Для каждого интерактивного элемента добавляйте логику приложения там, где сгенерирован комментарий TODO. Состояние вроде `state.Slider_2_val` сохраняется между кадрами. Radio-группы хранятся отдельно в `state.radioGroups`.

Полный экспорт также содержит создание контекста, размеры окна, нужные цвета, шрифты и колбэки, основную функцию рисования и цикл `reaper.defer`. Вложенные контейнеры создают соответствующие области ImGui. Не переносите вызов draw list через границу дочернего окна без подходящих draw list и точки отсчёта.

Макет правьте в JSON-проекте и экспортируйте снова: часть размеров и координат рисунков находится прямо в вызовах, а не только в `pos`.
